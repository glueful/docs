Glueful provides a powerful fluent query builder that simplifies database operations with a clean, chainable API. The QueryBuilder offers database-agnostic operations with robust security features, comprehensive logging, and advanced query capabilities.

## Basic Usage

The query builder allows for expressive, readable database operations:

```php
use Glueful\Database\Connection;

// Initialize connection
$connection = new Connection();

// Access QueryBuilder through connection table() method
$users = $connection->table('users')
    ->select(['id', 'name', 'email'])
    ->where('status', 'active')
    ->orderBy('name', 'ASC')
    ->limit(10)
    ->get();

// In controllers with dependency injection
class UsersController extends BaseController {
    private Connection $db;
    
    public function __construct(?Connection $connection = null) {
        $this->db = $connection ?? new Connection();
    }
    
    public function getActiveUsers() {
        return $this->db->table('users')
            ->select(['uuid', 'username', 'email'])
            ->where('status', 'active')
            ->whereNull('deleted_at')
            ->get();
    }
}
```

## Executing Raw SQL Queries

For complex SQL operations that can't be expressed through the QueryBuilder's fluent interface, Glueful provides raw SQL execution methods with proper parameter binding and security measures:

```php
// Execute raw SQL query and get all results (verified from actual QueryBuilder)
$results = $this->db->table('users')->executeRaw(
    'SELECT u.*, p.bio FROM users u LEFT JOIN profiles p ON u.id = p.user_id WHERE u.status = ? AND u.created_at > ?',
    ['active', '2025-01-01']
);

// Execute raw SQL and get first result only
$user = $this->db->table('users')->executeRawFirst(
    'SELECT * FROM users WHERE email = ? LIMIT 1',
    ['john@example.com']
);

// Complex analytical query with raw SQL
$analytics = $this->db->table('orders')->executeRaw("
    SELECT 
        DATE_FORMAT(created_at, '%Y-%m') as month,
        SUM(total) as revenue,
        COUNT(DISTINCT customer_id) as unique_customers,
        AVG(total) as avg_order_value
    FROM orders 
    WHERE status = ? 
    AND created_at >= DATE_SUB(NOW(), INTERVAL 6 MONTH)
    GROUP BY month
    ORDER BY month ASC
", ['completed']);

// Execute modification queries (INSERT, UPDATE, DELETE, DDL)
$affected = $this->db->table('users')->executeModification(
    'UPDATE users SET last_login = NOW() WHERE id = ?',
    [$userId]
);

// Database-specific optimizations with raw SQL
$topProducts = $this->db->table('products')->executeRaw("
    SELECT 
        p.name,
        p.views,
        RANK() OVER (ORDER BY p.views DESC) as popularity_rank
    FROM products p
    WHERE p.status = 'active'
    ORDER BY p.views DESC
    LIMIT 10
");
```

### Raw SQL Method Reference

**`executeRaw(string $sql, array $bindings = []): array`**
- Executes raw SQL and returns all result rows
- Returns empty array if no results
- Use for SELECT queries that return multiple rows

**`executeRawFirst(string $sql, array $bindings = []): ?array`**
- Executes raw SQL and returns first result row only
- Returns null if no results found
- Convenient for single-record lookups

**`executeModification(string $sql, array $bindings = []): int`**
- Executes modification queries (INSERT, UPDATE, DELETE, DDL)
- Returns number of affected rows
- Use for operations that don't return result data

### Security and Best Practices

⚠️ **Critical Security Warning**: Raw SQL methods execute queries directly without validation. Always use parameter bindings:

```php
// SAFE - Using parameter bindings
$users = $this->db->table('users')->executeRaw(
    'SELECT * FROM users WHERE status = ? AND role = ?',
    [$status, $role]
);

// DANGEROUS - String concatenation (SQL injection risk)
$users = $this->db->table('users')->executeRaw(
    "SELECT * FROM users WHERE status = '$status' AND role = '$role'"
);
```

### When to Use Raw SQL

Raw SQL is appropriate for:
- Complex analytical queries with window functions, CTEs, or advanced aggregations
- Database-specific optimizations and query hints
- Queries using database-specific functions not supported by QueryBuilder
- Performance-critical queries requiring precise SQL control
- Dynamic SQL where query structure varies significantly based on runtime conditions

## Upsert Operations

Glueful provides database-agnostic upsert functionality that handles INSERT or UPDATE operations seamlessly:

```php
// Insert new user or update existing one (verified from actual QueryBuilder usage)
$affected = $this->db->table('users')->upsert(
    [
        'username' => 'john_doe',
        'email' => 'john@example.com',
        'name' => 'John Doe',
        'status' => 'active'
    ],
    ['email', 'name', 'status'] // Columns to update on duplicate key
);

// Upsert with counter increment (from QueryBuilder documentation)
$affected = $this->db->table('page_views')->upsert(
    [
        'page' => '/home',
        'views' => 1,
        'last_viewed' => date('Y-m-d H:i:s')
    ],
    ['views' => 'views + 1', 'last_viewed'] // Increment views, update timestamp
);

// Batch upsert with array of records (actual pattern from DatabaseController)
$records = [
    ['sku' => 'PROD-001', 'name' => 'Product 1', 'price' => 99.99],
    ['sku' => 'PROD-002', 'name' => 'Product 2', 'price' => 149.99],
    ['sku' => 'PROD-003', 'name' => 'Product 3', 'price' => 199.99]
];

foreach ($records as $record) {
    $this->db->table('products')->upsert($record, ['name', 'price']);
}

// Complex upsert with conditional updates
$affected = $this->db->table('user_stats')->upsert(
    [
        'user_id' => $userId,
        'login_count' => 1,
        'last_login' => date('Y-m-d H:i:s'),
        'total_sessions' => 1
    ],
    [
        'login_count' => 'login_count + 1',
        'last_login',
        'total_sessions' => 'total_sessions + 1'
    ]
);
```

### Database-Specific Implementation

The upsert operation adapts to your database engine:

- **MySQL**: Uses `INSERT ... ON DUPLICATE KEY UPDATE`
- **PostgreSQL**: Uses `INSERT ... ON CONFLICT DO UPDATE`  
- **SQLite**: Uses `INSERT ... ON CONFLICT DO UPDATE` (SQLite 3.24+)

### Return Values

The upsert method returns the number of affected rows:
- `0`: No operation performed (rare edge case)
- `1`: New record inserted
- `2`: Existing record updated (MySQL behavior)
- `1`: Existing record updated (PostgreSQL/SQLite behavior)

## Best Practices

1. **Use Parameter Binding**: Always use parameter binding instead of string concatenation to protect against SQL injection.

```php
// GOOD (parameter binding)
$db->where(['email' => $email]);
$db->rawQuery("SELECT * FROM users WHERE email = ?", [$email]);

// BAD (vulnerable to SQL injection)
$db->whereRaw("email = '" . $email . "'");
$db->rawQuery("SELECT * FROM users WHERE email = '" . $email . "'");
```

2. **Use Transactions**: Wrap multiple related operations in transactions to ensure database consistency.

3. **Consider Soft Deletes**: Use soft deletes for important data to prevent permanent data loss.

4. **Optimize Pagination**: Be mindful of pagination with large datasets. Consider using indexed columns.

5. **DB-Agnostic Queries**: Use the query builder's database-agnostic features instead of writing raw SQL when possible.

6. **Prefer Query Builder Over Raw SQL**: When possible, use the query builder instead of raw SQL for better maintainability and security.
