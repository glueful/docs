Glueful features a completely redesigned extension system with individual manifest.json files, SPA support, and high-performance architecture.

## Extension System v2.0 Architecture

The Glueful extension system v2.0 is a high-performance, enterprise-grade module system that provides:

- **Individual Manifests**: Each extension has its own `manifest.json` file with schema version 2.0
- **SPA Integration**: Built-in Single Page Application support with Vue.js frameworks
- **Service Provider Architecture**: Deep integration with Symfony DI container
- **Central Configuration**: Global `extensions.json` for enabled extensions and environment settings
- **Advanced CLI Tooling**: Comprehensive commands for management, debugging, and optimization
- **Health Monitoring**: Built-in health checks, metrics, and performance benchmarking

Key architectural improvements in v2.0:
- **Individual manifests**: Each extension manages its own metadata in `manifest.json`
- **SPA support**: Extensions can provide web interfaces with Vue.js integration
- **Service providers**: Extensions register services using Symfony ContainerBuilder
- **Environment-aware**: Different extension sets for development vs production
- **Dependency resolution**: Automatic dependency validation and conflict detection

Every Glueful extension extends the base `\Glueful\Extensions` abstract class and can optionally provide service providers for DI container integration.

## Directory Structure

Extensions follow a standardized directory structure with individual manifest files and optional SPA support:

```
glueful/
├── extensions/                 # Main extensions directory
│   ├── ExtensionName/          # Individual extension directory (PascalCase)
│   │   ├── ExtensionName.php   # Main extension class (same name as folder)
│   │   ├── manifest.json       # Extension manifest (v2.0 schema)
│   │   ├── composer.json       # Composer dependencies (optional)
│   │   ├── README.md           # Documentation
│   │   ├── CHANGELOG.md        # Version history
│   │   ├── assets/             # Static assets (icons, images)
│   │   │   └── icon.png        # Extension icon
│   │   ├── public/             # SPA build output (if SPA enabled)
│   │   │   ├── index.html      # SPA entry point
│   │   │   └── assets/         # Built JavaScript/CSS assets
│   │   ├── screenshots/        # Extension screenshots for admin UI
│   │   ├── migrations/         # Database migrations (if needed)
│   │   ├── src/                # Source code directory
│   │   │   ├── Controllers/    # Extension controllers
│   │   │   ├── Services/       # Extension services
│   │   │   ├── routes.php      # Extension routes
│   │   │   └── config.php      # Extension configuration
│   │   └── tests/              # Extension tests
│   ├── extensions.json         # Central extension configuration
│   └── README.md               # Extension development guide
└── config/
    └── extensions.php          # Legacy configuration (deprecated)
```

Each extension has its own `manifest.json` file that defines metadata, dependencies, and capabilities. The central `extensions.json` file manages which extensions are enabled in different environments.

## Extension Manifest (manifest.json)

Each extension defines its metadata and configuration in a `manifest.json` file using schema version 2.0:

```json
{
  "manifestVersion": "2.0",
  "id": "admin",
  "name": "Admin",
  "displayName": "Admin Dashboard",
  "version": "0.19.0",
  "description": "Comprehensive admin dashboard UI",
  "author": {
    "name": "Glueful Team",
    "email": "dev@glueful.com",
    "url": "https://glueful.com"
  },
  "license": "MIT",
  "main": "./Admin.php",
  "main_class": "Glueful\\Extensions\\Admin",
  "autoload": {
    "psr-4": {
      "Glueful\\Extensions\\Admin\\": "src/"
    }
  },
  "engines": {
    "glueful": ">=0.27.0",
    "php": ">=8.2.0"
  },
  "dependencies": {
    "composer": {},
    "extensions": []
  },
  "provides": {
    "services": ["AdminServiceProvider"],
    "routes": ["extensions/Admin/src/routes.php"],
    "commands": [],
    "middleware": []
  },
  "spa": {
    "enabled": true,
    "configurations": [
      {
        "path_prefix": "/ui/api/admin",
        "build_path": "public/index.html",
        "name": "Admin Panel",
        "framework": "vue",
        "auth_required": false
      }
    ]
  }
}
```

### Namespaces and Autoloading

Extensions use PSR-4 autoloading defined in their individual `manifest.json` files. The main extension class uses the namespace `Glueful\Extensions\ExtensionName`:

```php
namespace Glueful\Extensions;

class Admin extends \Glueful\Extensions
{
    // Extension implementation
}
```

Subdirectories within an extension follow the PSR-4 mapping:

```php
// For src/Services/AdminService.php
namespace Glueful\Extensions\Admin\Services;

class AdminService 
{
    // Service implementation
}
```

The autoload configuration in `manifest.json` automatically registers these namespaces when the extension is loaded.

## Central Extension Configuration (extensions.json)

The central `extensions.json` file manages which extensions are enabled across different environments:

```json
{
  "schema_version": "2.0",
  "extensions": {
    "EmailNotification": {
      "version": "1.0.0",
      "enabled": true,
      "type": "core",
      "description": "Provides email notification functionality",
      "installPath": "extensions/EmailNotification",
      "autoload": {
        "psr-4": {
          "Glueful\\Extensions\\EmailNotification\\": "extensions/EmailNotification/src/"
        }
      }
    },
    "Admin": {
      "version": "0.19.0",
      "enabled": true,
      "type": "optional",
      "description": "Administrative interface",
      "installPath": "extensions/Admin"
    }
  },
  "environments": {
    "development": {
      "enabledExtensions": ["EmailNotification", "Admin", "RBAC"],
      "debug_mode": true
    },
    "production": {
      "enabledExtensions": ["EmailNotification", "Admin"],
      "debug_mode": false
    }
  }
}
```

## Extension Types

Glueful categorizes extensions into different types:

- **Core Extensions**: Essential components required for framework operation (e.g., EmailNotification)
- **Optional Extensions**: Additional functionality that can be enabled/disabled (e.g., Admin, RBAC, SocialLogin)

The type determines protection levels - core extensions require `--force` flag to disable.

## SPA (Single Page Application) Support

Extensions can provide modern web interfaces using the SPA configuration in `manifest.json`:

```json
{
  "spa": {
    "enabled": true,
    "configurations": [
      {
        "path_prefix": "/ui/api/admin",
        "build_path": "public/index.html",
        "name": "Admin Panel",
        "description": "Administrative interface",
        "framework": "vue",
        "auth_required": false,
        "permissions": [],
        "assets_path": "public/assets"
      }
    ]
  }
}
```

### SPA Configuration Options

- **path_prefix**: URL path where the SPA is accessible
- **build_path**: Path to the built SPA entry point (usually `public/index.html`)
- **framework**: Frontend framework used (vue, react, angular, etc.)
- **auth_required**: Whether authentication is required to access the SPA
- **permissions**: Required permissions for access
- **assets_path**: Path to built assets (CSS, JS files)

### SPA Directory Structure

When SPA is enabled, extensions include a `public/` directory:

```
ExtensionName/
├── manifest.json
└── public/              # SPA build output
    ├── index.html       # SPA entry point
    └── assets/          # Built assets
        ├── app-abc123.js
        └── app-abc123.css
```

The framework automatically serves these assets and routes SPA requests to the correct extension.

## Service Provider Integration

Extensions integrate with the Symfony DI container through service providers defined in their `manifest.json`:

```json
{
  "provides": {
    "services": ["AdminServiceProvider"],
    "routes": ["extensions/Admin/src/routes.php"],
    "commands": [],
    "middleware": []
  }
}
```

### Creating Service Providers

Extension service providers follow the Symfony DI pattern:

```php
// extensions/Admin/src/AdminServiceProvider.php
namespace Glueful\Extensions\Admin;

use Glueful\DI\ServiceProviderInterface;
use Symfony\Component\DependencyInjection\ContainerBuilder;
use Symfony\Component\DependencyInjection\Reference;

class AdminServiceProvider implements ServiceProviderInterface
{
    public function register(ContainerBuilder $container): void
    {
        // Register extension services
        $container->register(AdminController::class)
            ->setArguments([new Reference('database')])
            ->setPublic(true);
    }

    public function boot(Container $container): void
    {
        // Post-compilation setup
    }

    public function getName(): string
    {
        return 'admin';
    }

    public function getCompilerPasses(): array
    {
        return [];
    }
}
```

### Environment-Specific Behavior

Extensions can be enabled/disabled per environment in `extensions.json`:

- **Development**: Full extension set including debugging tools
- **Production**: Only essential extensions for performance

Core extensions are protected and require `--force` flag to disable.

## Extension Lifecycle

Extensions follow a defined lifecycle managed by the ExtensionsManager:

1. **Discovery**: ExtensionsManager reads individual `manifest.json` files and central `extensions.json`
2. **Validation**: Manifest schema validation and dependency checking
3. **Loading**: Enabled extensions have their namespaces registered with PSR-4 autoloader
4. **Service Registration**: Extension service providers are registered with Symfony DI container
5. **Initialization**: Each extension's `initialize()` method is called
6. **Boot**: Service providers' `boot()` methods are called after container compilation
7. **Request Processing**: Extension functionality is available for HTTP requests and CLI commands

### Key Lifecycle Methods

All extensions must implement these core methods:

```php
// Required by IExtensions interface
public static function process(array $queryParams, array $bodyParams): array;

// Common extension lifecycle methods
public static function initialize(): void;
public static function registerServices(): void;
public static function registerMiddleware(): void;
public static function getMetadata(): array;
```

#### Middleware Integration

The `registerMiddleware()` method allows extensions to hook into the application's HTTP middleware pipeline. Extensions can register custom middleware components that process HTTP requests and responses:

```php
public static function registerMiddleware(): void
{
    // Register middleware with the application's pipeline
    $app = \Glueful\App::getInstance();
    $app->middleware()->add(YourMiddlewareClass::class);
}
```

#### Environment-Specific Configuration

Extensions can control whether they should be enabled in specific environments (development, staging, production) using the `isEnabledForEnvironment()` method:

```php
public static function isEnabledForEnvironment(string $environment): bool
{
    // Only enable in production and staging environments
    return in_array($environment, ['production', 'staging']);
    
    // Or for development-only extensions:
    // return $environment === 'development';
}
```

## Creating Extensions

To create a new extension for Glueful, follow these steps:

1. Create a new directory in the `extensions/` folder with a PascalCase name
2. Create a main extension class that extends `\Glueful\Extensions`
3. Implement the required lifecycle methods
4. Create configuration and route files as needed
5. Enable the extension in `config/extensions.php`

Example of a basic extension:

```php
<?php
declare(strict_types=1);

namespace Glueful\Extensions;

/**
 * YourExtension
 * @description Description of your extension
 * @version 1.0.0
 */
class YourExtension extends \Glueful\Extensions
{
    /** @var array Configuration for the extension */
    private static array $config = [];
    
    public static function initialize(): void
    {
        // Load configuration
        if (file_exists(__DIR__ . '/config.php')) {
            self::$config = require __DIR__ . '/config.php';
        }
        
        // Set up your extension
    }
    
    public static function registerServices(): void
    {
        // Register services
    }
    
    public static function process(array $queryParams, array $bodyParams): array
    {
        // Handle extension requests
        $action = $queryParams['action'] ?? 'default';
        
        return [
            'success' => true,
            'code' => 200,
            'data' => [
                'extension' => 'YourExtension',
                'message' => 'Extension is working properly'
            ]
        ];
    }
    
    public static function getMetadata(): array
    {
        return [
            'name' => 'YourExtension',
            'description' => 'Description of your extension',
            'version' => '1.0.0',
            'author' => 'Your Name',
            'type' => 'optional', // 'core' or 'optional'
            'requires' => [
                'glueful' => '>=1.0.0',
                'php' => '>=8.1.0',
                'extensions' => [] // List of required extensions
            ]
        ];
    }
}
```

### Real-World Extension Example: SocialLogin

Here's a simplified example based on the actual SocialLogin extension in Glueful:

```php
<?php
declare(strict_types=1);

namespace Glueful\Extensions;

use Glueful\Auth\AuthBootstrap;
use Glueful\Extensions\SocialLogin\Providers\GoogleAuthProvider;
use Glueful\Extensions\SocialLogin\Providers\FacebookAuthProvider;
use Glueful\Helpers\ExtensionsManager;

/**
 * Social Login Extension
 * @description Provides social authentication through Google, Facebook and GitHub
 * @version 1.0.0
 */
class SocialLogin extends \Glueful\Extensions
{
    /** @var array Configuration for the extension */
    private static array $config = [];
    
    /** @var array Supported social providers */
    private static array $supportedProviders = ['google', 'facebook', 'github'];
    
    public static function initialize(): void
    {
        // Load configuration
        self::loadConfig();
        
        // Register providers with the authentication system
        self::registerAuthProviders();
    }
    
    private static function loadConfig(): void
    {
        // Default configuration
        $defaultConfig = [
            'enabled_providers' => ['google', 'facebook', 'github'],
            'auto_register' => true,
            'link_accounts' => true,
        ];
        
        // Try to load config from file
        $configPath = ExtensionsManager::getConfigPath() . '/extensions/social_login.php';
        if (file_exists($configPath)) {
            $loadedConfig = require $configPath;
            self::$config = array_merge($defaultConfig, $loadedConfig);
        } else {
            self::$config = $defaultConfig;
        }
    }
    
    private static function registerAuthProviders(): void
    {
        // Initialize the authentication system
        $authManager = AuthBootstrap::getManager();
        
        // Register providers based on configuration
        $enabledProviders = self::$config['enabled_providers'] ?? [];
        
        // Register each configured provider
        foreach ($enabledProviders as $provider) {
            try {
                switch ($provider) {
                    case 'google':
                        $instance = new GoogleAuthProvider();
                        $authManager->registerProvider('google', $instance);
                        break;
                    case 'facebook':
                        $instance = new FacebookAuthProvider();
                        $authManager->registerProvider('facebook', $instance);
                        break;
                }
            } catch (\Exception $e) {
                error_log("Failed to register {$provider} auth provider: " . $e->getMessage());
            }
        }
    }
    
    public static function getMetadata(): array
    {
        return [
            'name' => 'Social Login',
            'description' => 'Provides social authentication through Google, Facebook and GitHub',
            'version' => '1.0.0',
            'author' => 'Glueful Extensions Team',
            'type' => 'optional',
            'requires' => [
                'glueful' => '>=1.0.0',
                'php' => '>=8.1.0',
                'extensions' => []
            ]
        ];
    }
}
```

## Configuration

Extensions are configured in the `config/extensions.php` file:

```php
<?php
return [
    // Core extensions that are essential for framework functionality
    'core' => [
        'EmailNotification',
        'UserManagement'
    ],
    
    // Optional extensions that can be enabled/disabled as needed
    'optional' => [
        'SocialLogin',
        'Analytics'
    ],
    
    // All enabled extensions (both core and optional)
    'enabled' => [
        'EmailNotification',
        'UserManagement',
        'SocialLogin'
    ],
    
    'paths' => [
        'extensions' => '/path/to/extensions'
    ]
];
```

Individual extensions can also have their own configuration files, typically located at `extensions/ExtensionName/config.php`.

## Extension Metadata

Extensions should provide metadata through the `getMetadata()` method. This information is used for dependency tracking, displaying extension information in the admin UI, and ensuring compatibility.

Required metadata fields include:
- `name`: Display name of the extension
- `description`: Brief description of what the extension does
- `version`: Semantic version (e.g., "1.0.0")
- `author`: Author name or organization
- `type`: Extension type ('core' or 'optional')
- `requires`: Object containing dependency requirements

Example metadata:

```php
public static function getMetadata(): array
{
    return [
        'name' => 'SocialLogin',
        'description' => 'Adds social authentication capabilities',
        'version' => '1.2.0',
        'author' => 'Glueful Team',
        'type' => 'optional',
        'requires' => [
            'glueful' => '>=1.0.0',
            'php' => '>=8.1.0',
            'extensions' => ['UserManagement']
        ]
    ];
}
```

## Best Practices

1. **Use manifest.json schema 2.0**: Always include `"manifestVersion": "2.0"` in your manifest
2. **Define complete metadata**: Include author, version, dependencies, and engine requirements
3. **Use PSR-4 autoloading**: Follow the standard autoload mapping in manifest.json
4. **Register service providers**: Use Symfony DI container for dependency injection
5. **Test SPA configurations**: Verify SPA paths and asset references work correctly
6. **Document your extension**: Include comprehensive README and CHANGELOG files
7. **Handle environments**: Consider different behavior for development vs production
8. **Use proper namespacing**: Follow `Glueful\Extensions\YourExtension` pattern

## Troubleshooting

### Extension Not Loading

1. **Check enabled status**:
   ```bash
   php glueful extensions:info
   ```

2. **Validate manifest**:
   ```bash
   php glueful extensions:validate ExtensionName
   ```

3. **Check logs**: Review application logs for extension errors

### Manifest Issues

1. **Validate JSON syntax**: Ensure `manifest.json` is valid JSON with schema version 2.0
2. **Check autoload paths**: Verify PSR-4 mappings point to correct directories
3. **Verify service providers**: Ensure service provider classes exist and implement proper interface

### SPA Not Loading

1. **Check build path**: Verify `public/index.html` exists and is accessible
2. **Validate assets**: Ensure built assets are in the correct `public/assets/` directory
3. **Review path prefix**: Confirm SPA path_prefix doesn't conflict with other routes

### Performance Issues

1. **Run benchmarks**:
   ```bash
   php glueful extensions:benchmark
   ```

2. **Get debug information**:
   ```bash
   php glueful extensions:debug
   ```

For more detailed debugging, check the extension's individual log files and validate that all dependencies are properly installed.
