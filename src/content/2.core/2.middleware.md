This section covers Glueful's enterprise middleware system, including security components, performance optimization, monitoring, and custom middleware development.

## Enterprise Middleware Stack

Glueful provides a comprehensive PSR-15 compatible middleware stack with security, performance, and monitoring capabilities built for production environments.

### Core Security Middleware

The security middleware stack provides multiple layers of protection with modern implementations:

### AuthenticationMiddleware

PSR-15 compatible authentication middleware with flexible provider support:

```php
use Glueful\Http\Middleware\AuthenticationMiddleware;

// Standard authentication
$authMiddleware = new AuthenticationMiddleware();

// Admin-only authentication
$adminAuthMiddleware = new AuthenticationMiddleware(
    requiresAdmin: true,
    authManager: container()->get(AuthenticationManager::class),
    providerNames: ['jwt', 'api_key'],
    container: app()
);

// Usage in middleware stack
class AuthenticatedRoute implements RequestHandlerInterface
{
    public function handle(Request $request): Response
    {
        $authMiddleware = new AuthenticationMiddleware();
        return $authMiddleware->process($request, $this);
    }
}
```

### RateLimiterMiddleware

Adaptive rate limiting with behavior analysis and ML-powered anomaly detection:

```php
use Glueful\Http\Middleware\RateLimiterMiddleware;

// Standard rate limiting (100 requests per hour)
$rateLimiter = new RateLimiterMiddleware(
    maxAttempts: 100,
    windowSeconds: 3600,
    type: 'ip',
    useAdaptiveLimiter: false,
    enableDistributed: false,
    container: app()
);

// Adaptive rate limiting with threat detection
$adaptiveRateLimiter = new RateLimiterMiddleware(
    maxAttempts: 100,
    windowSeconds: 3600,
    type: 'user',
    useAdaptiveLimiter: true,        // ML-powered behavior analysis
    enableDistributed: true,         // Multi-node rate limiting
    container: app()
);

// Usage in middleware pipeline
class RateLimitedRoute implements RequestHandlerInterface
{
    public function handle(Request $request): Response
    {
        $rateLimiter = new RateLimiterMiddleware(60, 60, 'ip');
        return $rateLimiter->process($request, $this);
    }
}
```

### CORS Handling

Cross-Origin Resource Sharing (CORS) is handled by the dedicated `Cors` class rather than middleware:

```php
use Glueful\Http\Cors;

// In your bootstrap or request handling
$cors = new Cors(); // Uses config-based CORS
if (!$cors->handle()) {
    return; // OPTIONS request handled
}

// Or use factory methods for different scenarios
$cors = Cors::development(); // Localhost configurations
$cors = Cors::production(['https://yourapp.com']); // Production setup
$cors = Cors::universal(); // Allow all origins (use with caution)

if (!$cors->handle()) {
    return;
}
```

For detailed CORS configuration, see the [API Development](./api-development) documentation.

### PermissionMiddleware

Role-Based Access Control (RBAC) with context-aware permissions:

```php
// Basic permission checking
Router::addMiddleware(new PermissionMiddleware([
    'resource' => 'users',
    'action' => 'read'
]));

// Context-aware permissions
Router::addMiddleware(new PermissionMiddleware([
    'permission_rules' => [
        'users.read' => ['resource' => 'users', 'context_required' => false],
        'users.edit' => ['resource' => 'users', 'context_required' => true],
        'users.delete' => ['resource' => 'users', 'admin_only' => true]
    ],
    'route_mapping' => [
        'GET /api/users' => 'users.read',
        'PUT /api/users/{id}' => 'users.edit',
        'DELETE /api/users/{id}' => 'users.delete'
    ],
    'context_extractors' => [
        'user_id' => function($request) {
            return $request->get('id');
        }
    ],
    'cache_permissions' => true,
    'audit_access_attempts' => true
]));
```

### CSRFMiddleware

Cross-Site Request Forgery protection for forms and state-changing operations:

```php

    'header_name' => 'X-CSRF-Token',
    'exclude_routes' => ['/api/*'],
    'regenerate_on_use' => true
]));
```

## Custom Middleware

You can create custom PSR-15 compatible middleware by implementing the `MiddlewareInterface`:

```php
<?php
declare(strict_types=1);

namespace App\Http\Middleware;

use Glueful\Http\Middleware\MiddlewareInterface;
use Glueful\Http\Middleware\RequestHandlerInterface;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpFoundation\JsonResponse;

class ApiVersionMiddleware implements MiddlewareInterface
{
    private string $supportedVersion;
    
    public function __construct(string $supportedVersion = '1.0')
    {
        $this->supportedVersion = $supportedVersion;
    }
    
    public function process(Request $request, RequestHandlerInterface $handler): Response
    {
        // Extract API version from request header
        $requestedVersion = $request->headers->get('X-API-Version');
        
        // Check if version is supported
        if ($requestedVersion && $requestedVersion !== $this->supportedVersion) {
            return new JsonResponse([
                'success' => false,
                'message' => 'API version not supported',
                'code' => 400
            ], 400);
        }
        
        // Add the API version to the response
        $response = $handler->handle($request);
        $response->headers->set('X-API-Version', $this->supportedVersion);
        
        return $response;
    }
}
```

Then use it in your application:

```php
use App\Http\Middleware\ApiVersionMiddleware;

// Use in a route handler
class VersionedApiHandler implements RequestHandlerInterface
{
    public function handle(Request $request): Response
    {
        $versionMiddleware = new ApiVersionMiddleware('2.0');
        return $versionMiddleware->process($request, $this);
    }
}
```

### Middleware with Dependencies

You can inject services from the DI container into your middleware:

```php
use Glueful\Database\Connection;
use Glueful\DI\Interfaces\ContainerInterface;

class DatabaseTransactionMiddleware implements MiddlewareInterface
{
    private Connection $connection;
    
    public function __construct(?ContainerInterface $container = null)
    {
        $this->connection = ($container ?? app())->get(Connection::class);
    }
    
    public function process(Request $request, RequestHandlerInterface $handler): Response
    {
        // Start transaction
        $this->connection->beginTransaction();
        
        try {
            // Process request
            $response = $handler->handle($request);
            
            // Commit transaction if successful
            $this->connection->commit();
            
            return $response;
        } catch (\Throwable $e) {
            // Rollback transaction on error
            $this->connection->rollBack();
            throw $e;
        }
    }
}
```

### Conditional Middleware

You can create middleware that only runs under certain conditions:

```php
class ConditionalMiddleware implements MiddlewareInterface
{
    private MiddlewareInterface $middleware;
    private callable $condition;
    
    public function __construct(MiddlewareInterface $middleware, callable $condition)
    {
        $this->middleware = $middleware;
        $this->condition = $condition;
    }
    
    public function process(Request $request, RequestHandlerInterface $handler): Response
    {
        if (call_user_func($this->condition, $request)) {
            return $this->middleware->process($request, $handler);
        }
        
        return $handler->handle($request);
    }
}

// Usage example
$onlyInProduction = function(Request $request) {
    return config('app.env') === 'production';
};

Router::addMiddleware(new ConditionalMiddleware(
    new SecurityHeadersMiddleware(),
    $onlyInProduction
));
```

## Middleware Ordering

The order of middleware registration significantly affects how requests are processed. Here's a recommended order for middleware registration:

1. **Error Handling Middleware** - Catches exceptions and errors
2. **Security Middleware** - CORS, security headers, etc.
3. **Session/State Middleware** - Manages user sessions
4. **Authentication Middleware** - Verifies user identity
5. **Rate Limiting Middleware** - Controls request rates
6. **Logging Middleware** - Records request details
7. **Content Negotiation Middleware** - Handles Accept headers
8. **Body Parsing Middleware** - Processes request body
9. **Route-specific Middleware** - Custom middleware for specific routes

Example configuration:

```php
Router::addMiddlewares([
    new SecurityHeadersMiddleware(),
    new AuthenticationMiddleware(),
    new RateLimiterMiddleware(),
    new PermissionMiddleware(),
    new CSRFMiddleware(),
    new LoggerMiddleware(),
    new ApiMetricsMiddleware(),
]);
```

## Middleware Registration Patterns

### Global Middleware

Register middleware that should run for all requests:

```php
// In your bootstrap file
use Glueful\Http\Router;
use Glueful\Http\Middleware\CorsMiddleware;
use Glueful\Http\Middleware\LoggerMiddleware;
use Glueful\Http\Middleware\SecurityHeadersMiddleware;

// Individual registration
Router::addMiddleware(new CorsMiddleware());
Router::addMiddleware(new LoggerMiddleware());

// Or register multiple middleware at once
Router::addMiddlewares([
    new SecurityHeadersMiddleware(),
    new RateLimiterMiddleware(60, 60),
]);
```

### Route-Specific Middleware

For certain routes or route groups:

```php
// Protect admin routes with authentication
Router::group('/admin', function() {
    Router::get('/stats', [AdminController::class, 'stats']);
    Router::get('/users', [AdminController::class, 'users']);
}, requiresAuth: true, requiresAdminAuth: true);

// Apply rate limiting to auth endpoints
$authRateLimiter = new RateLimiterMiddleware(5, 60); // 5 attempts per minute

Router::group('/auth', function() {
    Router::post('/login', [AuthController::class, 'login']);
    Router::post('/register', [AuthController::class, 'register']);
});

// Add the middleware to the router
Router::addMiddleware($authRateLimiter);
```

## Best Practices

### Performance Optimization

1. **Minimize Middleware Stack**: Only include necessary middleware
2. **Cache Configuration**: Cache middleware configuration for better performance
3. **Conditional Execution**: Use conditional middleware to avoid unnecessary processing
4. **Async Processing**: Use async logging and audit middleware where possible

### Security Guidelines

1. **Layer Security**: Use multiple security middleware layers
2. **Validate Input**: Always validate and sanitize input in middleware
3. **Rate Limiting**: Implement adaptive rate limiting for production
4. **Audit Everything**: Log security-relevant events comprehensively

### Development Tips

1. **Test Middleware**: Write unit tests for custom middleware
2. **Monitor Performance**: Track middleware execution time
3. **Use DI Container**: Leverage dependency injection for services
4. **Follow PSR-15**: Stick to PSR-15 standards for compatibility
