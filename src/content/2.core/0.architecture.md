This section provides a comprehensive overview of Glueful's modern, enterprise-grade architecture and design patterns.

## Core Architecture Principles

Glueful is built on four foundational principles that guide its enterprise-grade design:

### 1. Dependency Injection First
The framework is built around a sophisticated DI container system that manages all service dependencies, promoting loose coupling and testability.

### 2. Performance by Design
Every component is optimized for enterprise workloads with features like connection pooling, query optimization, memory management, and caching strategies.

### 3. Security Throughout
Security is not an afterthought—it's integrated into every layer with RBAC, CSRF protection, rate limiting, vulnerability scanning, and lockdown modes.

### 4. Extensible Foundation
The modular extension system allows for clean separation of concerns while maintaining high performance and easy maintenance.

## Dependency Injection Container

The DI container is the heart of Glueful's architecture, managing all service dependencies and providing enterprise-grade features.

### Container Bootstrap

The container is initialized in `bootstrap.php` with service providers:

```php
<?php
// bootstrap.php
use Glueful\DI\Container;
use Glueful\DI\ServiceProviders;

// Initialize container
$container = new Container();

// Register service providers
$providers = [
    \Glueful\DI\Providers\CoreServiceProvider::class,
    \Glueful\DI\ServiceProviders\SecurityServiceProvider::class,
    \Glueful\DI\ServiceProviders\RequestServiceProvider::class,
    \Glueful\DI\Providers\RepositoryServiceProvider::class,
    \Glueful\DI\Providers\ControllerServiceProvider::class,
    \Glueful\DI\Providers\QueueServiceProvider::class,
    \Glueful\DI\Providers\ArchiveServiceProvider::class,
    \Glueful\DI\Providers\ExtensionServiceProvider::class,
];

foreach ($providers as $providerClass) {
    $provider = new $providerClass();
    $provider->register($container);
}

// Make container globally available
container($container);
```

### Service Provider Pattern

Service providers organize related services and their dependencies:

```php
<?php
namespace Glueful\DI\ServiceProviders;

use Glueful\DI\Container;
use Glueful\DI\Interfaces\ServiceProviderInterface;
use Glueful\Security\SecureSerializer;

class SecurityServiceProvider implements ServiceProviderInterface
{
    public function register(ContainerInterface $container): void
    {
        // Register SecureSerializer instances for different use cases
        $container->singleton('serializer.cache', function () {
            return SecureSerializer::forCache();
        });

        $container->singleton('serializer.queue', function () {
            return SecureSerializer::forQueue();
        });

        $container->singleton(SecureSerializer::class, function () {
            return new SecureSerializer();
        });
    }
}
```

### Container Usage

Access services throughout your application:

```php
// In controllers, services, or anywhere
$secureSerializer = container()->get(SecureSerializer::class);
$cacheSerializer = container()->get('serializer.cache');
$queueSerializer = container()->get('serializer.queue');
```

## Core Components

### 1. Bootstrap System

The bootstrap system initializes the framework with comprehensive setup including DI container initialization, security validation, and performance monitoring.

### 2. Router Layer

The router (`Glueful\Http\Router`) handles URL routing with built-in authentication and middleware support:

```php
use Glueful\Http\Router;

// Basic routing with authentication
Router::get('/users', [UserController::class, 'index'], requiresAuth: true);
Router::post('/admin/users', [AdminController::class, 'create'], 
    requiresAuth: true, requiresAdminAuth: true);

// Route groups with shared middleware
Router::group('/api/v1', function() {
    Router::get('/profile', [ProfileController::class, 'show']);
    Router::put('/profile', [ProfileController::class, 'update']);
}, requiresAuth: true);
```

### 3. Middleware Layer

PSR-15 compatible middleware stack with enterprise features:

```php
use Glueful\Http\Middleware;

// Security middleware stack
Router::addMiddlewares([
    new Middleware\SecurityHeadersMiddleware(),
    new Middleware\CorsMiddleware(),
    new Middleware\RateLimiterMiddleware(),
    new Middleware\AuthenticationMiddleware(),
    new Middleware\PermissionMiddleware(),

```

### 4. Controller Layer

```php
    use AsyncAuditTrait;

    // Enterprise-ready controller foundation with:
    // - Built-in permission checking

    // - Response and query caching

    // - User context management
}
```

### 5. Service Layer

Business logic layer with dependency injection:

```php
<?php
namespace App\Services;

class UserService
{
    public function __construct(
        private UserRepository $userRepository,
        private NotificationService $notifications,
        private AuditLogger $auditLogger
    ) {}
    
    public function createUser(array $userData): User
    {
        $user = $this->userRepository->create($userData);
        
        // Send welcome notification
        $this->notifications->send(
            'user.welcome', $user, 'Welcome to the platform!',
            ['username' => $user->username]
        );
        
        // Audit the action
        $this->auditLogger->log('user.created', [
            'user_id' => $user->uuid,
            'action' => 'user_created'
        ]);
        
        return $user;
    }
}
```

### 6. Repository Layer

Data access layer with query optimization:

```php
<?php
namespace App\Repository;

use Glueful\Repository\BaseRepository;

class UserRepository extends BaseRepository
{
    protected string $table = 'users';
    
    public function findActiveUsers(): array
    {
        return $this->db->select($this->table)
            ->where(['status' => 'active'])
            ->where('deleted_at', 'IS', null)
            ->orderBy(['created_at' => 'DESC'])
            ->get();
    }
    
    public function findByEmailWithProfile(string $email): ?array
    {
        return $this->db->select($this->table)
            ->join('user_profiles', 'users.uuid = user_profiles.user_uuid')
            ->where(['users.email' => $email])
            ->first();
    }
}
```

### 7. Database Layer

Enterprise database features with connection pooling:

```php
// Connection pooling configuration
$db = container()->get(DatabaseInterface::class);

// Uses connection pool automatically
$users = $db->select('users')->where(['active' => true])->get();

// Transactions with pool management
$db->transaction(function($db) {
    $userId = $db->insert('users', $userData);
    $db->insert('user_profiles', ['user_id' => $userId, ...]);
});
```

## Data Flow Architecture

### Request Lifecycle

1. **HTTP Request** arrives at the application
2. **Router** matches the request to a route and extracts parameters
3. **Middleware Stack** processes the request (security, auth, rate limiting)
4. **Controller** is instantiated via DI container with dependencies
5. **Service Layer** handles business logic with injected dependencies
6. **Repository Layer** manages data access with connection pooling
7. **Database** executes optimized queries with caching
8. **Response** is formatted and cached appropriately
9. **Middleware Stack** processes the response (headers, compression)
10. **HTTP Response** is sent to the client

### Async Processing

Background job processing with the queue system:

```php
// Queue a job
$queueService = container()->get(QueueService::class);
$queueService->dispatch(new SendNotificationJob($user, $notification));

// Process jobs
php glueful queue:work
```

### Event System

Event-driven architecture for loose coupling:

```php
// Dispatch events
$eventDispatcher = container()->get(EventDispatcher::class);
$eventDispatcher->dispatch(new UserCreatedEvent($user));

// Listen for events
class UserCreatedListener
{
    public function handle(UserCreatedEvent $event): void
    {
        // Handle the event
    }
}
```

## Security Architecture

### Defense in Depth

1. **Network Layer**: HTTPS, firewall rules, DDoS protection
2. **Application Layer**: Security headers, CORS, input validation
3. **Authentication Layer**: JWT tokens, session management via TokenStorageService
4. **Authorization Layer**: RBAC with fine-grained permissions
5. **Data Layer**: Encryption at rest, secure database connections
6. **Audit Layer**: Comprehensive audit logging

### Threat Mitigation

- **Object Injection**: SecureSerializer with class whitelisting
- **SQL Injection**: Parameterized queries and input validation
- **XSS**: Output encoding and CSP headers
- **CSRF**: Token-based CSRF protection
- **Session Hijacking**: Secure session management with caching
- **Rate Limiting**: Adaptive rate limiting with threat detection
- **Data Exposure**: Field-level access control
- **Serialization Attacks**: Safe serialization patterns
