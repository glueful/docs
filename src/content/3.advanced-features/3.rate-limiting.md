Glueful provides built-in rate limiting capabilities to protect your API from abuse and ensure fair usage. The framework implements a sliding window algorithm for precise rate limiting that can be applied to different contexts.

## Overview

The Glueful rate limiting system provides enterprise-grade request throttling with advanced capabilities:

### Core Features
- **Sliding Window Algorithm** - Precise request tracking using Redis sorted sets
- **Multiple Limiting Types** - IP-based, user-based, endpoint-specific, and custom limiting
- **Audit Logging Integration** - All rate limit events are logged for security monitoring
- **Redis/Memcached Integration** - High-performance cache backend support
- **Standard HTTP Responses** - Proper 429 responses with rate limit headers
- **PSR-15 Middleware** - Easy integration with any PSR-15 compatible framework

### Advanced Features
- **Adaptive Rate Limiting** - Behavior-based limiting with anomaly detection
- **Dynamic Rules System** - Real-time configurable rules with priorities and conditions
- **Distributed Rate Limiting** - Cross-node coordination for cluster deployments
- **Progressive Rate Limiting** - Adjusts limits based on behavior scores
- **Machine Learning Integration** - ML-powered threshold adjustment and attack detection
- **Request Context Tracking** - Enhanced request profiling and analysis

## How Rate Limiting Works

### Standard Rate Limiting

The `RateLimiter` class uses Redis sorted sets for precise sliding window rate limiting:

1. **Timestamp Recording** - Stores request timestamps using `ZADD` with score = timestamp
2. **Window Cleanup** - Removes expired entries using `ZREMRANGEBYSCORE`
3. **Count Verification** - Checks current count using `ZCARD`
4. **Audit Logging** - Records all rate limit events for security monitoring

### Adaptive Rate Limiting

The `AdaptiveRateLimiter` extends standard limiting with intelligent behavior analysis:

1. **Behavior Profiling** - Analyzes request patterns and user behavior
2. **Anomaly Detection** - Identifies suspicious activities using behavior scores
3. **Dynamic Adjustment** - Applies stricter limits based on threat levels
4. **Rule Application** - Evaluates dynamic rules with priorities and conditions
5. **Progressive Limiting** - Gradually restricts access for suspicious behavior

### Distributed Rate Limiting

The `RateLimiterDistributor` coordinates limits across multiple nodes:

1. **Node Registration** - Registers application nodes with the distributor
2. **Global Synchronization** - Shares rate limit data across nodes
3. **Primary Coordinator** - Elects a primary node for coordination
4. **Cross-Node Communication** - Uses Redis pub/sub for real-time updates

## Configuration

Rate limiting can be configured at multiple levels with extensive customization options.

### Environment Configuration

Add to your `.env` file:

```env
# Rate Limiting Configuration
RATE_LIMIT_ENABLED=true
RATE_LIMIT_ADAPTIVE=true
RATE_LIMIT_DISTRIBUTED=false
RATE_LIMIT_ML_ENABLED=false
RATE_LIMIT_DEFAULT_ATTEMPTS=60
RATE_LIMIT_DEFAULT_WINDOW=60

# Redis Configuration for Rate Limiting
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=
REDIS_DB=0
```

### Application Configuration

Configure in `config/security.php`:

```php
return [
    'rate_limiter' => [
        'enabled' => env('RATE_LIMIT_ENABLED', true),
        'enable_adaptive' => env('RATE_LIMIT_ADAPTIVE', false),
        'enable_distributed' => env('RATE_LIMIT_DISTRIBUTED', false),
        'enable_ml' => env('RATE_LIMIT_ML_ENABLED', false),
        
        'default_limits' => [
            'max_attempts' => env('RATE_LIMIT_DEFAULT_ATTEMPTS', 60),
            'window_seconds' => env('RATE_LIMIT_DEFAULT_WINDOW', 60),
        ],
        
        'progressive_limiting' => [
            'enabled' => true,
            'behavior_threshold' => 0.6,
            'max_reduction_factor' => 0.5,
        ],
        
        'distributed' => [
            'sync_interval' => 30,
            'node_timeout' => 300,
            'cleanup_interval' => 3600,
        ],
    ],
];
```

### Basic Configuration Options

- `maxAttempts`: Maximum requests allowed in the time window
- `windowSeconds`: Time window duration in seconds
- `type`: Rate limiting strategy (ip, user, endpoint, custom)
- `useAdaptiveLimiter`: Enable adaptive rate limiting
- `enableDistributed`: Enable distributed rate limiting
- `mlEnabled`: Enable machine learning features

## Basic Usage

### Standard Rate Limiting

```php
use Glueful\Security\RateLimiter;

// Allow 100 requests per minute
$limiter = new RateLimiter(
    key: 'api-endpoint',
    maxAttempts: 100,
    windowSeconds: 60
);

if ($limiter->attempt()) {
    // Process the request
    return handleRequest();
} else {
    $retryAfter = $limiter->getRetryAfter();
    return [
        'error' => 'Rate limit exceeded',
        'retry_after' => $retryAfter,
        'remaining' => $limiter->remaining()
    ];
}
```

### Adaptive Rate Limiting

```php
use Glueful\Security\AdaptiveRateLimiter;
use Glueful\Http\RequestContext;

// Create request context for behavior analysis
$context = [
    'ip' => $_SERVER['REMOTE_ADDR'],
    'user_agent' => $_SERVER['HTTP_USER_AGENT'],
    'method' => $_SERVER['REQUEST_METHOD'],
    'path' => $_SERVER['REQUEST_URI'],
    'timestamp' => time(),
];

// Allow 100 requests per minute with adaptive behavior
$limiter = new AdaptiveRateLimiter(
    key: 'api-endpoint',
    maxAttempts: 100,
    windowSeconds: 60,
    context: $context,
    enableDistributed: false
);

if ($limiter->attempt()) {
    // Process the request
    return handleRequest();
} else {
    // Get information about applied rules
    $activeRules = $limiter->getActiveApplicableRules();
    
    return [
        'error' => 'Rate limit exceeded',
        'retry_after' => $limiter->getRetryAfter(),
        'remaining' => $limiter->remaining(),
        'adaptive' => true,
        'rules_applied' => array_keys($activeRules)
    ];
}
```

## Helper Methods

Glueful provides convenient helper methods for common rate limiting scenarios with built-in audit logging:

### IP-based Rate Limiting

```php
// Limit by IP: 60 attempts per minute
$limiter = RateLimiter::perIp(
    ip: $_SERVER['REMOTE_ADDR'],
    maxAttempts: 60,
    windowSeconds: 60
);

// Automatically logs IP-based rate limiter creation for security monitoring
```

### User-based Rate Limiting

```php
// Limit by user: 1000 requests per day
$limiter = RateLimiter::perUser(
    userId: $user->getId(),
    maxAttempts: 1000,
    windowSeconds: 86400
);

// Automatically logs user-based rate limiter creation with user ID
```

### Endpoint-specific Rate Limiting

```php
// Limit specific endpoint: 30 attempts per minute
$limiter = RateLimiter::perEndpoint(
    endpoint: 'search',
    identifier: $userId,
    maxAttempts: 30,
    windowSeconds: 60
);

// Automatically logs endpoint-specific rate limiter creation
```

## Available Methods

### RateLimiter Class

The base `RateLimiter` class provides these key methods:

- `attempt()`: Returns true if attempt is allowed, false if rate limited (with audit logging)
- `remaining()`: Get remaining attempts in current window
- `getRetryAfter()`: Get seconds until rate limit resets
- `reset()`: Reset the rate limiter (with audit logging)
- `isExceeded()`: Check if rate limit is exceeded

### AdaptiveRateLimiter Class

The `AdaptiveRateLimiter` extends the base class with:

- `getActiveApplicableRules()`: Get rules currently applied based on behavior score
- `addRule(RateLimiterRule $rule)`: Add a dynamic rule to the limiter
- `getBehaviorScore()`: Get current behavior score (0.0-1.0)
- `updateBehaviorProfile()`: Update behavior profile with current request

### RateLimiterRule Class

Dynamic rules provide real-time configuration:

- `setMaxAttempts(int $maxAttempts)`: Update maximum attempts
- `setWindowSeconds(int $windowSeconds)`: Update time window
- `setThreshold(float $threshold)`: Set activation threshold (0.0-1.0)
- `addCondition(string $key, $value)`: Add rule condition
- `activate()` / `deactivate()`: Enable/disable rule
- `setPriority(int $priority)`: Set rule priority

## Middleware Implementation

Glueful provides a comprehensive PSR-15 compatible middleware with support for adaptive and distributed rate limiting:

### Basic Middleware Usage

```php
use Glueful\Http\Middleware\RateLimiterMiddleware;

// Basic rate limiting middleware
Router::addMiddleware(new RateLimiterMiddleware(
    maxAttempts: 60,
    windowSeconds: 60,
    type: 'ip'
));

// Apply to specific routes
Router::get('/api/search', 'SearchController@index')
    ->middleware(new RateLimiterMiddleware(30, 60, 'endpoint'));
```

### Advanced Middleware Usage

```php
// Adaptive rate limiting with distributed support
Router::addMiddleware(new RateLimiterMiddleware(
    maxAttempts: 100,
    windowSeconds: 60,
    type: 'user',
    useAdaptiveLimiter: true,
    enableDistributed: true
));

// Configuration-based middleware
Router::addMiddleware(new RateLimiterMiddleware(
    maxAttempts: config('security.rate_limiter.default_limits.max_attempts'),
    windowSeconds: config('security.rate_limiter.default_limits.window_seconds'),
    type: 'ip',
    useAdaptiveLimiter: config('security.rate_limiter.enable_adaptive'),
    enableDistributed: config('security.rate_limiter.enable_distributed')
));
```

### Middleware Features

- **Automatic User Detection** - Extracts user ID from JWT tokens
- **Context Creation** - Builds request context for behavior analysis
- **Exception Handling** - Throws `RateLimitExceededException` for proper error handling
- **Header Management** - Adds comprehensive rate limit headers
- **Adaptive Headers** - Includes adaptive-specific headers when enabled

## Response Headers

When rate limiting is applied, the following headers are included in responses:

### Standard Headers

- `X-RateLimit-Limit`: Maximum number of requests permitted in window
- `X-RateLimit-Remaining`: Number of requests remaining in current window
- `X-RateLimit-Reset`: Unix timestamp when the rate limit window resets
- `Retry-After`: Seconds until requests may resume (only on 429 responses)

### Adaptive Rate Limiting Headers

When adaptive rate limiting is enabled:

- `X-Adaptive-RateLimit`: Set to "true" when adaptive limiting is active
- `X-Distributed-RateLimit`: Set to "true" when distributed limiting is enabled

### Enhanced 429 Response

When adaptive rate limiting blocks a request:

```json
{
    "success": false,
    "message": "Too Many Requests",
    "retry_after": 45,
    "remaining": 0,
    "code": 429,
    "adaptive": true,
    "rules_applied": ["high_suspicion_rule", "progressive_limit"]
}
```

## Technical Details

### Standard Rate Limiting

The Glueful rate limiter offers these technical advantages:

- **Sliding Window Algorithm** - Uses Redis sorted sets (ZADD, ZREMRANGEBYSCORE, ZCARD)
- **Precise Timestamp Tracking** - Stores exact request timestamps, not just counts
- **Automatic Cleanup** - Removes expired attempts automatically
- **Thread-Safe Implementation** - Redis operations are atomic
- **Efficient Memory Usage** - Uses TTL expiration for data management
- **Audit Integration** - All operations logged via AuditLogger

### Adaptive Rate Limiting

Advanced features include:

- **Behavior Profiling** - Tracks request patterns and user behavior
- **Anomaly Detection** - Identifies suspicious activities using behavior scores
- **Progressive Limiting** - Applies stricter limits based on threat levels
- **Dynamic Rules** - Real-time configurable rules with priorities
- **Machine Learning** - Optional ML integration for threshold adjustment
- **RequestContext Integration** - Enhanced request tracking and analysis

### Distributed Rate Limiting

For multi-node deployments:

- **Cross-Node Coordination** - Shares rate limit data across application nodes
- **Primary Coordinator Election** - Automatic leader election for coordination
- **Global Limit Synchronization** - Maintains consistent limits cluster-wide
- **Node Health Monitoring** - Tracks and manages node availability
- **Redis Pub/Sub** - Real-time communication between nodes
- **Distributed Locking** - Prevents race conditions in limit updates

## Best Practices

1. Use appropriate window sizes for your use case
2. Include rate limit headers in responses
3. Implement graceful fallback handling

## Advanced Features

### Dynamic Rules System

Create and manage rate limiting rules dynamically:

```php
use Glueful\Security\RateLimiterRule;
use Glueful\Security\AdaptiveRateLimiter;

// Create a rule for high-risk behavior
$highRiskRule = new RateLimiterRule(
    id: 'high_risk_behavior',
    name: 'High Risk Behavior Rule',
    description: 'Stricter limits for suspicious behavior',
    maxAttempts: 10,
    windowSeconds: 60,
    threshold: 0.7,        // Activate when behavior score >= 0.7
    conditions: [
        'min_requests' => 5,
        'suspicious_patterns' => true
    ],
    active: true,
    priority: 100
);

// Add rule to adaptive rate limiter
$adaptiveLimiter = new AdaptiveRateLimiter('user:123', 60, 60, $context);
$adaptiveLimiter->addRule($highRiskRule);

// Update rule dynamically
$highRiskRule->setMaxAttempts(5)   // Even stricter
             ->setThreshold(0.6)   // Lower activation threshold
             ->addCondition('ip_reputation', 'low');
```

### Distributed Rate Limiting

Set up distributed rate limiting across multiple nodes:

```php
use Glueful\Security\RateLimiterDistributor;

// Initialize distributor (typically in application bootstrap)
$distributor = new RateLimiterDistributor(
    nodeId: 'web-server-01',
    syncInterval: 30
);

// Enable distributed limiting in adaptive rate limiter
$limiter = new AdaptiveRateLimiter(
    key: 'api-endpoint',
    maxAttempts: 100,
    windowSeconds: 60,
    context: $context,
    enableDistributed: true
);

// Check if this node is the primary coordinator
if ($distributor->isPrimaryCoordinator()) {
    // Perform cleanup and synchronization tasks
    $distributor->cleanupInactiveNodes();
    $distributor->synchronizeGlobalLimits();
}

// Get cluster information
$nodes = $distributor->getNodes();
echo "Active nodes: " . count($nodes);
```

### Behavior Analysis

The adaptive rate limiter analyzes request patterns:

```php
// Request context for behavior analysis
$context = [
    'ip' => $request->getClientIp(),
    'user_agent' => $request->headers->get('User-Agent'),
    'method' => $request->getMethod(),
    'path' => $request->getPathInfo(),
    'query_count' => count($request->query->all()),
    'timestamp' => time(),
    'referrer' => $request->headers->get('Referer'),
    'content_length' => $request->headers->get('Content-Length', 0),
];

$adaptiveLimiter = new AdaptiveRateLimiter(
    'user:' . $userId,
    100,
    60,
    $context
);

// Check behavior score after request
if ($adaptiveLimiter->attempt()) {
    $behaviorScore = $adaptiveLimiter->getBehaviorScore();
    
    if ($behaviorScore > 0.8) {
        // High suspicion - log for security review
        logger()->warning('High behavior score detected', [
            'user_id' => $userId,
            'behavior_score' => $behaviorScore,
            'ip' => $context['ip']
        ]);
    }
}
```

## Performance Considerations

### Redis Configuration

For optimal performance, configure Redis properly:

```php
// config/cache.php
return [
    'default' => 'redis',
    'stores' => [
        'redis' => [
            'driver' => 'redis',
            'host' => env('REDIS_HOST', '127.0.0.1'),
            'port' => env('REDIS_PORT', 6379),
            'password' => env('REDIS_PASSWORD'),
            'database' => env('REDIS_DB', 0),
            'options' => [
                'prefix' => env('REDIS_PREFIX', 'glueful_'),
                'serializer' => Redis::SERIALIZER_MSGPACK,  // Faster serialization
                'compression' => Redis::COMPRESSION_LZ4,   // Optional compression
            ],
        ],
    ],
];
```

### Memory Usage

- **Standard Rate Limiting**: ~100 bytes per active limit
- **Adaptive Rate Limiting**: ~500 bytes per active limit (includes behavior data)
- **Distributed Rate Limiting**: Additional ~200 bytes per node for coordination

### Performance Benchmarks

- **Redis Operations**: 10,000+ requests/second per core
- **Behavior Analysis**: Adds ~1-2ms per request
- **Distributed Coordination**: Adds ~2-5ms per request

## Integration with Cache System

The rate limiter integrates deeply with Glueful's cache system:

### Cache Backend Requirements

- **Redis**: Recommended for production (supports sorted sets)
- **Memcached**: Basic support (limited adaptive features)
- **File Cache**: Development only (not recommended)

### Cache Key Patterns

- Standard limits: `rate_limit:{key}`
- Behavior profiles: `behavior_profile:{tracking_id}`
- Anomaly scores: `anomaly_score:{tracking_id}`
- Distributed nodes: `rate_limit_distributor:nodes:{node_id}`
- Global limits: `rate_limit_distributor:global_limits:{key}`

### Cache Operations

```php
// Example Redis operations for rate limiting
REDIS> ZADD rate_limit:user:123 1640995200 1640995200
REDIS> ZREMRANGEBYSCORE rate_limit:user:123 -inf 1640995140
REDIS> ZCARD rate_limit:user:123
REDIS> EXPIRE rate_limit:user:123 60
```
