Glueful provides a powerful dependency injection (DI) container that manages service instantiation, dependency resolution, and lifecycle management throughout the application. The container supports auto-wiring, service providers, and advanced binding strategies.

## Overview

The Glueful DI Container offers:

- **Auto-wiring** - Automatic dependency resolution using reflection
- **Service Providers** - Organized service registration with lifecycle management
- **Flexible Bindings** - Support for singletons, transients, closures, and aliases
- **Method Injection** - Call methods with automatic dependency resolution
- **Extension Support** - Easy integration for custom services and extensions
- **Production Optimized** - Efficient service resolution and memory management

## Quick Start

### Basic Container Usage

```php
use Glueful\DI\Container;

// Create container instance
$container = new Container();

// Bind a service
$container->bind(UserService::class, UserService::class);

// Bind a singleton
$container->singleton(DatabaseConnection::class, function($container) {
    return new DatabaseConnection(
        host: env('DB_HOST'),
        database: env('DB_DATABASE')
    );
});

// Resolve services
$userService = $container->get(UserService::class);
$dbConnection = $container->get(DatabaseConnection::class);
```

### Using the Global Container

```php
// Access the global container
$container = app();

// Or resolve services directly
$userService = app(UserService::class);

// Using the container helper function
$service = container()->get(MyService::class);
```

## Container Features

### Service Binding

The container supports multiple binding strategies:

#### Basic Binding

```php
// Bind interface to implementation
$container->bind(UserRepositoryInterface::class, UserRepository::class);

// Bind with closure
$container->bind(EmailService::class, function($container) {
    return new EmailService(
        $container->get(MailerInterface::class),
        config('mail.from')
    );
});

// Bind as singleton
$container->singleton(CacheManager::class, function($container) {
    return new CacheManager(
        $container->get(CacheDriverInterface::class)
    );
});
```

#### Instance Binding

```php
// Bind existing instance
$config = new ConfigManager();
$container->instance(ConfigManager::class, $config);

// Bind value objects
$container->instance('app.version', '1.0.0');
$container->instance('app.debug', env('APP_DEBUG', false));
```

#### Aliases

```php
// Create aliases for easier access
$container->alias('db', DatabaseConnection::class);
$container->alias('cache', CacheManager::class);

// Use aliases
$db = $container->get('db');
$cache = $container->get('cache');
```

### Auto-wiring

The container automatically resolves constructor dependencies:

```php
class UserService
{
    public function __construct(
        private UserRepository $userRepo,
        private EmailService $emailService,
        private LoggerInterface $logger
    ) {}
}

// Container automatically resolves all dependencies
$userService = $container->get(UserService::class);
```

#### Auto-wiring Features

- **Type-hint Resolution** - Resolves based on parameter type hints
- **Default Values** - Uses parameter defaults when resolution fails
- **Nullable Parameters** - Returns null for optional dependencies
- **Interface Resolution** - Resolves interfaces to bound implementations

### Method Injection

Call methods with automatic dependency resolution:

```php
class NotificationService
{
    public function send(
        User $user,
        EmailService $emailService,
        string $template
    ): bool {
        return $emailService->send($user->email, $template);
    }
}

// Call method with auto-resolved dependencies
$result = $container->call([new NotificationService(), 'send'], [
    'user' => $user,
    'template' => 'welcome'
]);

// Or with closure
$result = $container->call(function(UserService $userService, $userId) {
    return $userService->find($userId);
}, ['userId' => 123]);
```

## Service Providers

Service providers organize service registration and provide lifecycle management:

### Creating Service Providers

```php
use Glueful\DI\Interfaces\ServiceProviderInterface;
use Glueful\DI\Interfaces\ContainerInterface;

class UserServiceProvider implements ServiceProviderInterface
{
    public function register(ContainerInterface $container): void
    {
        // Register services during the registration phase
        $container->singleton(UserRepository::class, function($container) {
            return new UserRepository(
                $container->get(DatabaseConnection::class)
            );
        });

        $container->bind(UserService::class, function($container) {
            return new UserService(
                $container->get(UserRepository::class),
                $container->get(EmailService::class)
            );
        });

        // Register interfaces
        $container->bind(UserRepositoryInterface::class, UserRepository::class);
    }

    public function boot(ContainerInterface $container): void
    {
        // Perform initialization after all services are registered
        $userService = $container->get(UserService::class);
        $userService->initializeDefaults();
        
        // Set up event listeners, etc.
    }
}
```

### Built-in Service Providers

Glueful includes several built-in service providers:

#### CoreServiceProvider

Registers essential framework services:

- **Database Services** - Connection, QueryBuilder, SchemaManager
- **Cache Services** - CacheDriverInterface and factory
- **Authentication** - TokenManager, AuthenticationManager
- **Security** - RandomStringGenerator
- **Performance** - MemoryManager
- **Configuration** - ConfigManager
- **Request** - Symfony Request instance

#### RepositoryServiceProvider

Registers data repositories:

```php
// Example repository registrations
$container->singleton(UserRepository::class);
$container->singleton(ProductRepository::class);
$container->singleton(OrderRepository::class);
```

#### SecurityServiceProvider

Registers security-related services:

```php
// Secure serialization services
$container->singleton('serializer.cache', function() {
    return SecureSerializer::forCache();
});

$container->singleton('serializer.queue', function() {
    return SecureSerializer::forQueue();
});
```

### Registering Service Providers

```php
// Register during container initialization
$container->register(new UserServiceProvider());
$container->register(new EmailServiceProvider());

// Boot all providers
$container->boot();

// Or use the bootstrap system
use Glueful\DI\ContainerBootstrap;

ContainerBootstrap::registerProvider(new CustomServiceProvider());
```

## Container Bootstrap

The `ContainerBootstrap` class provides centralized container management:

### Initialization

```php
use Glueful\DI\ContainerBootstrap;

// Initialize container with core services
$container = ContainerBootstrap::initialize();

// Get the initialized container
$container = ContainerBootstrap::getContainer();
```

### Custom Bindings

```php
// Add custom bindings
ContainerBootstrap::addBindings([
    UserServiceInterface::class => UserService::class,
    'api.version' => 'v2',
    CacheInterface::class => [
        'class' => RedisCache::class,
        'singleton' => true
    ]
]);
```

### Testing Support

```php
// Reset container for testing
ContainerBootstrap::reset();

// Initialize test container
$testContainer = ContainerBootstrap::initialize();
```

## Advanced Usage

### Contextual Binding

```php
// Bind different implementations based on context
$container->bind(LoggerInterface::class, function($container) {
    if (env('APP_ENV') === 'production') {
        return new ProductionLogger();
    }
    return new DevelopmentLogger();
});

// Environment-specific services
$container->singleton(CacheDriver::class, function($container) {
    $driver = env('CACHE_DRIVER', 'redis');
    
    return match($driver) {
        'redis' => new RedisCache(),
        'memcached' => new MemcachedCache(),
        'file' => new FileCache(),
        default => throw new \InvalidArgumentException("Unsupported cache driver: $driver")
    };
});
```

### Lazy Loading

```php
// Services are only instantiated when first resolved
$container->singleton(ExpensiveService::class, function($container) {
    // This closure only runs when ExpensiveService is first requested
    return new ExpensiveService(
        $container->get(DatabaseConnection::class),
        $container->get(CacheManager::class)
    );
});
```

### Conditional Registration

```php
class DebugServiceProvider implements ServiceProviderInterface
{
    public function register(ContainerInterface $container): void
    {
        if (env('APP_DEBUG', false)) {
            $container->singleton(DebugBar::class, function($container) {
                return new DebugBar();
            });
            
            $container->singleton(QueryLogger::class, function($container) {
                return new QueryLogger();
            });
        }
    }
}
```

### Extension Integration

```php
// Extensions can register their services
class MyExtensionServiceProvider implements ServiceProviderInterface
{
    public function register(ContainerInterface $container): void
    {
        $container->singleton(ExtensionService::class, function($container) {
            return new ExtensionService(
                $container->get(DatabaseConnection::class)
            );
        });
    }
    
    public function boot(ContainerInterface $container): void
    {
        // Initialize extension after all services are available
        $extensionService = $container->get(ExtensionService::class);
        $extensionService->initialize();
    }
}

// Register extension provider
ContainerBootstrap::registerProvider(new MyExtensionServiceProvider());
```

## Integration Examples

### Database Integration

```php
// Register database services
$container->singleton(Connection::class, function($container) {
    return new Connection();
});

$container->bind(QueryBuilder::class, function($container) {
    $connection = $container->get(Connection::class);
    return new QueryBuilder($connection->getPDO(), $connection->getDriver());
});

// Use in repositories
class UserRepository
{
    public function __construct(
        private QueryBuilder $queryBuilder
    ) {}
    
    public function findById(int $id): ?User
    {
        return $this->queryBuilder
            ->select('users', ['*'])
            ->where(['id' => $id])
            ->first();
    }
}
```

### Cache Integration

```php
// Register cache services
$container->singleton(CacheDriverInterface::class, function($container) {
    return CacheFactory::create();
});

// Use in services
class ProductService
{
    public function __construct(
        private ProductRepository $repository,
        private CacheDriverInterface $cache
    ) {}
    
    public function getProduct(int $id): Product
    {
        return $this->cache->remember("product.$id", 3600, function() use ($id) {
            return $this->repository->find($id);
        });
    }
}
```

### Authentication Integration

```php
// Register authentication services
$container->singleton(TokenManager::class, function($container) {
    return new TokenManager();
});

$container->singleton(AuthenticationManager::class, function($container) {
    return new AuthenticationManager();
});

// Use in middleware
class AuthMiddleware
{
    public function __construct(
        private AuthenticationManager $auth
    ) {}
    
    public function handle(Request $request): bool
    {
        $token = $request->headers->get('Authorization');
        return $this->auth->validateToken($token);
    }
}
```

## Performance Considerations

### Service Resolution

- **Singleton Performance** - Singletons are resolved once and cached
- **Reflection Overhead** - Auto-wiring uses reflection, but instances are cached
- **Memory Usage** - Container stores bindings and singleton instances

### Optimization Tips

```php
// Prefer singletons for expensive services
$container->singleton(DatabaseConnection::class, $factory);

// Use instances for frequently accessed services
$container->instance('app.config', $config);

// Avoid complex closures in hot paths
$container->bind(SimpleService::class); // Auto-wired is often faster

// Preload critical services
$container->get(CriticalService::class); // Force early resolution
```

### Memory Management

```php
// Container automatically manages singleton lifecycles
// No manual cleanup needed for most use cases

// For long-running processes, consider service scoping
class RequestScopedService
{
    // Services that should be fresh per request
}

// Register as transient rather than singleton
$container->bind(RequestScopedService::class);
```

## Best Practices

### Service Design

1. **Constructor Injection** - Prefer constructor injection over setter injection
2. **Interface Segregation** - Use specific interfaces rather than large ones
3. **Single Responsibility** - Keep services focused on one concern
4. **Dependency Minimization** - Avoid too many constructor parameters

### Container Usage

1. **Service Provider Organization** - Group related services in providers
2. **Environment Configuration** - Use environment variables for configuration
3. **Testing** - Use container reset in tests for isolation
4. **Extension Points** - Design services to be easily extended

### Error Handling

```php
try {
    $service = $container->get(NonExistentService::class);
} catch (ServiceNotFoundException $e) {
    // Handle missing service
    logger()->error("Service not found: " . $e->getMessage());
}

try {
    $result = $container->call([$service, 'method'], $params);
} catch (ContainerException $e) {
    // Handle container errors
    logger()->error("Container error: " . $e->getMessage());
}
```

## Troubleshooting

### Common Issues

**Service not found:**
- Verify service is registered in a service provider
- Check for typos in class names
- Ensure service provider is registered and booted

**Circular dependency:**
- Use lazy loading with closures
- Consider breaking the circular dependency with events
- Use setter injection as a last resort

**Auto-wiring fails:**
- Ensure all dependencies have type hints
- Check that interfaces are bound to implementations
- Verify constructor parameters are resolvable

**Memory leaks:**
- Avoid storing large objects in singleton services
- Consider using transient services for request-scoped data
- Monitor container size in long-running processes

The Glueful DI Container provides a robust foundation for building maintainable and testable applications with proper separation of concerns and automatic dependency management.
