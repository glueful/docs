Glueful provides a powerful and flexible queue system for managing background jobs, batch processing, and asynchronous task execution. The system supports multiple queue drivers and includes comprehensive monitoring, failure handling, and configuration management.

## Overview

The Glueful queue system offers:

- **Multiple Queue Drivers** - Redis, Database, Beanstalkd support
- **Worker Management** - Daemon mode with memory limits and timeouts
- **Failed Job Handling** - Comprehensive retry, recovery, and analysis
- **Real-time Monitoring** - Live queue metrics and performance tracking
- **Configuration Management** - Dynamic configuration validation and testing
- **Batch Processing** - Efficient handling of related job groups

## Quick Start

### Basic Queue Operations

```bash
# Start processing queue jobs
php glueful queue work

# Run worker as daemon with memory limit
php glueful queue work --daemon --memory=512

# Monitor queue status in real-time
php glueful queue status

# View real-time metrics
php glueful queue monitor
```

### Configuration

Configure your queue settings in `config/queue.php`:

```php
return [
    'default' => env('QUEUE_CONNECTION', 'redis'),
    
    'connections' => [
        'redis' => [
            'driver' => 'redis',
            'connection' => 'default',
            'queue' => env('REDIS_QUEUE', 'default'),
            'retry_after' => 90,
            'block_for' => null,
        ],
        
        'database' => [
            'driver' => 'database',
            'table' => 'jobs',
            'queue' => 'default',
            'retry_after' => 90,
        ],
        
        'beanstalkd' => [
            'driver' => 'beanstalkd',
            'host' => 'localhost',
            'queue' => 'default',
            'retry_after' => 90,
            'block_for' => 0,
        ],
    ],
    
    'failed' => [
        'driver' => 'database',
        'database' => env('DB_CONNECTION', 'mysql'),
        'table' => 'failed_jobs',
    ],
];
```

## Programming Interface

### Creating Jobs

Create job classes for background processing:

```php
<?php

namespace App\Jobs;

use Glueful\Queue\Job;

class ProcessUserRegistration extends Job
{
    protected $user;
    
    public function __construct($user)
    {
        $this->user = $user;
    }
    
    public function handle()
    {
        // Send welcome email
        $this->sendWelcomeEmail($this->user);
        
        // Create user profile
        $this->createUserProfile($this->user);
        
        // Log registration
        $this->logRegistration($this->user);
    }
    
    public function failed(\Exception $exception)
    {
        // Handle job failure
        logger()->error('User registration failed', [
            'user_id' => $this->user['id'],
            'error' => $exception->getMessage()
        ]);
    }
}
```

### Dispatching Jobs

Queue jobs for background processing:

```php
use Glueful\Queue\QueueManager;
use App\Jobs\ProcessUserRegistration;

$queueManager = new QueueManager();

// Dispatch job to default queue
$queueManager->push(new ProcessUserRegistration($user));

// Dispatch to specific queue
$queueManager->pushOn('high-priority', new ProcessUserRegistration($user));

// Dispatch with delay
$queueManager->later(60, new ProcessUserRegistration($user)); // 60 seconds

// Dispatch with specific connection
$queueManager->connection('redis')->push(new ProcessUserRegistration($user));
```

## Advanced Features

### Batch Jobs

Process related jobs as a batch:

```php
use Glueful\Queue\Batch;
use App\Jobs\ProcessOrderItem;

// Create a batch of related jobs
$batch = new Batch([
    new ProcessOrderItem($order, $item1),
    new ProcessOrderItem($order, $item2),
    new ProcessOrderItem($order, $item3),
]);

// Dispatch batch with completion callback
$queueManager->batch($batch)
    ->then(function() {
        // All jobs completed successfully
        logger()->info('Order processing completed');
    })
    ->catch(function() {
        // One or more jobs failed
        logger()->error('Order processing failed');
    })
    ->dispatch();
```

### Custom Worker Options

Configure workers with custom options:

```php
use Glueful\Queue\Worker;
use Glueful\Queue\WorkerOptions;

$options = new WorkerOptions();
$options->setMemory(512)          // 512MB memory limit
        ->setTimeout(60)          // 60 second timeout
        ->setSleep(3)             // 3 second sleep between jobs
        ->setMaxTries(3)          // Maximum retry attempts
        ->setForce(false)         // Don't force worker in maintenance mode
        ->setStopWhenEmpty(false); // Keep running when queue is empty

$worker = new Worker($queueManager, $options);
$worker->daemon('redis', 'default', $options);
```

### Job Middleware

Add middleware to jobs for cross-cutting concerns:

```php
class ProcessOrder extends Job
{
    public function middleware()
    {
        return [
            new RateLimited('orders', 10), // Max 10 orders per minute
            new WithoutOverlapping($this->order->id), // Prevent duplicate processing
            new Authenticate('admin'), // Require admin authentication
        ];
    }
    
    public function handle()
    {
        // Process order
    }
}
```

## Production Considerations

### Performance Optimization

- **Use daemon mode** for production workers to avoid bootstrap overhead
- **Set appropriate memory limits** to prevent memory leaks
- **Use Redis** for high-performance queueing
- **Monitor queue depth** to prevent backlogs
- **Scale workers** based on queue load

### Monitoring and Alerting

Set up monitoring for queue health:

```php
// Monitor queue depth
if ($monitor->getMetrics()['pending_jobs'] > 1000) {
    // Alert: Queue backlog detected
    $alertService->send('Queue backlog detected');
}

// Monitor worker health
if ($monitor->getWorkerStats()['active_workers'] === 0) {
    // Alert: No active workers
    $alertService->send('No queue workers running');
}

// Monitor failure rate
if ($monitor->getMetrics()['success_rate'] < 0.95) {
    // Alert: High failure rate
    $alertService->send('High queue failure rate');
}
```

### Error Handling

Implement comprehensive error handling:

```php
class ProcessPayment extends Job
{
    public $tries = 3;
    public $timeout = 120;
    
    public function handle()
    {
        try {
            $this->processPayment();
        } catch (TemporaryException $e) {
            // Release job back to queue for retry
            $this->release(30); // Retry in 30 seconds
        } catch (PermanentException $e) {
            // Fail job permanently
            $this->fail($e);
        }
    }
    
    public function failed(\Exception $exception)
    {
        // Notify administrators
        $this->notifyAdministrators($exception);
        
        // Log failure details
        logger()->error('Payment processing failed', [
            'job_id' => $this->job->getJobId(),
            'attempts' => $this->attempts(),
            'error' => $exception->getMessage()
        ]);
    }
}
```

## Best Practices

### Job Design

- **Keep jobs small and focused** - Single responsibility principle
- **Make jobs idempotent** - Safe to run multiple times
- **Handle failures gracefully** - Implement proper error handling
- **Use appropriate timeouts** - Prevent jobs from running indefinitely
- **Log important events** - Track job progress and failures

### Queue Management

- **Use multiple queues** - Separate high and low priority jobs
- **Monitor queue health** - Set up alerts for failures and backlogs
- **Regular maintenance** - Clean up old failed jobs periodically
- **Test in staging** - Validate job behavior before production
- **Document job requirements** - Clear dependencies and expectations

### Performance

- **Batch related operations** - Group similar jobs together
- **Use appropriate drivers** - Redis for performance, database for reliability
- **Scale workers dynamically** - Based on queue load and time of day
- **Monitor resource usage** - Memory, CPU, and database connections
- **Optimize job payload** - Minimize data passed to jobs

## Troubleshooting

### Common Issues

**Workers not processing jobs:**
- Check worker status: `php glueful queue status`
- Verify configuration: `php glueful queue config validate`
- Test connectivity: `php glueful queue config test`

**High memory usage:**
- Reduce worker memory limit: `--memory=256`
- Check for memory leaks in job code
- Monitor with: `php glueful queue monitor`

**Failed jobs accumulating:**
- Review failed job details: `php glueful queue failed list`
- Check error patterns: `php glueful queue failed export`
- Fix underlying issues and retry: `php glueful queue failed retry all`

**Poor performance:**
- Monitor metrics: `php glueful queue monitor`
- Check queue depth and worker count
- Consider scaling workers or optimizing jobs
- Review database/Redis performance

The Glueful queue system provides a robust foundation for background job processing with comprehensive monitoring, failure handling, and performance optimization capabilities.
