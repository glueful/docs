Glueful provides comprehensive Role-Based Access Control (RBAC) through the **RBAC Extension** that delivers fine-grained permission management for your application resources.

## Architecture Overview

The RBAC extension in Glueful provides these core components:

- **Role Repository**: Hierarchical role management with caching
- **Permission Repository**: Comprehensive permission operations
- **Role Service**: Business logic for role operations
- **Permission Assignment Service**: User-role and role-permission assignments
- **Audit Service**: Permission change tracking and compliance
- **Validation Framework**: Role and permission validation constraints
- **Middleware Integration**: Route-level authorization enforcement

This extension-based architecture allows for flexible, performant access control that scales with application complexity.

## Permission Types

Glueful defines standard permission types that apply to all resources:

```php
// Core permission types
enum Permission: string {
    case VIEW = 'A';   // Read access
    case SAVE = 'B';   // Create new resources
    case DELETE = 'C'; // Delete resources
    case EDIT = 'D';   // Modify existing resources
}
```

These permissions can be combined to create custom access levels for any resource in your application.

## Role Management

Roles in Glueful represent collections of permissions that can be assigned to users:

```php
use Glueful\Extensions\RBAC\Repositories\RoleRepository;
use Glueful\Extensions\RBAC\Services\RoleService;

// Create a new role
$roleRepo = container()->get(RoleRepository::class);
$role = $roleRepo->createRole([
    'name' => 'editor',
    'slug' => 'editor',
    'description' => 'Content editor role',
    'level' => 2,
    'status' => 'active'
]);

// Assign a user to a role via UserRoleRepository
$userRoleRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\UserRoleRepository::class);
$userRoleRepo->assignRole($userUuid, $role->getUuid());

// Check if user has a specific role
$hasRole = $userRoleRepo->hasRole($userUuid, $role->getUuid());
```

### Built-in Roles

Glueful comes with pre-configured roles:

- **Superuser**: Full access to all resources and administrative functions
- **Admin**: Administrative access to most system features
- **User**: Standard authenticated user access
- **Guest**: Limited access for non-authenticated users

You can customize these roles or create your own to match your application's needs.

## Assigning Permissions

Permissions in Glueful are assigned to roles and can optionally be assigned directly to users:

```php
use Glueful\Extensions\RBAC\Repositories\{RolePermissionRepository, UserPermissionRepository};

// Assign permissions to a role
$rolePermissionRepo = container()->get(RolePermissionRepository::class);
$rolePermissionRepo->assignPermissions($roleUuid, [
    'resource' => 'users',
    'permissions' => ['view', 'create', 'edit'], // Modern permission names
    'scope' => 'global'
]);

// For direct user permissions (these override role permissions)
$userPermissionRepo = container()->get(UserPermissionRepository::class);
$userPermissionRepo->assignPermissions($userUuid, [
    'resource' => 'documents',
    'permissions' => ['view', 'create', 'edit', 'delete'],
    'scope' => 'owned' // User can only manage their own documents
]);
```

## Permission Checking

Glueful provides multiple ways to check permissions:

### Using the Permission Manager

```php
use Glueful\Extensions\RBAC\Services\PermissionAssignmentService;

// Check if the current user has permission to edit users
$permissionService = container()->get(PermissionAssignmentService::class);
if ($permissionService->hasPermission($userUuid, 'users', 'edit')) {
    // Allow user to edit
} else {
    return Response::forbidden('Insufficient permissions');
}
```

### Using Middleware

```php
use Glueful\Extensions\RBAC\Middleware\{PermissionMiddleware, RoleMiddleware};

// Protect a route with permission middleware
Router::get('/admin/users', function() use ($container) {
    $controller = $container->get(UserController::class);
    return $controller->index();
})->middleware(new PermissionMiddleware('users', 'view'));

// Group routes with role-based access
Router::group('/documents', function() use ($container) {
    Router::get('/', function() use ($container) {
        return $container->get(DocumentController::class)->index();
    });
    Router::post('/', function() use ($container) {
        return $container->get(DocumentController::class)->store();
    });
})->middleware(new RoleMiddleware(['editor', 'admin']));
```

## Resource-Specific Permissions

Glueful uses a model/resource naming convention for permissions:

- **API resources**: `api.{resource_name}` (e.g., `api.users`)
- **UI elements**: `ui.{view_name}` (e.g., `ui.dashboard`)
- **Extension resources**: `api.ext.{extension}.{resource}` (e.g., `api.ext.payments.transactions`)

This naming scheme allows for consistent permission management across your application.

## Permission Caching

For performance optimization, Glueful implements permission caching:

```php
// Get cached effective permissions through service
$permissionService = container()->get(PermissionAssignmentService::class);
$permissions = $permissionService->getUserEffectivePermissions($userUuid, $useCache = true);

// Invalidate cache when permissions change
$permissionService->clearUserPermissionCache($userUuid);
```

The cache is automatically refreshed when:
- User roles are changed
- Role permissions are updated
- Direct user permissions are modified

## Superuser Access

Superuser accounts have unrestricted access to all resources:

```php
// Check if user has system-level roles
$userRoleRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\UserRoleRepository::class);
$userRoles = $userRoleRepo->getUserRoles($userUuid);

foreach ($userRoles as $role) {
    if ($role->isSystem() && $role->getName() === 'superuser') {
        // System superuser bypasses permission checks
        // Proceed with operation
        break;
    }
}
```

This special role allows designated administrators to perform maintenance and troubleshooting without permission constraints.

## Model-Level Authorization

Implement fine-grained, resource-specific authorization that goes beyond basic RBAC:

### Document Ownership and Sharing Model

```php
class DocumentService 
{
    public function viewDocument(string $documentId, string $userUuid): ?array 
    {
        // Get document data
        $document = $this->documentRepo->find($documentId);
        
        if (!$document) {
            return null;
        }
        
        // Multi-layered authorization check
        if (!$this->canAccessDocument($document, $userUuid, 'A')) {
            throw new AuthorizationException('Access denied to document');
        }
        
        return $document;
    }
    
    private function canAccessDocument(array $document, string $userUuid, string $permission): bool
    {
        // 1. Check if user is document owner
        if ($document['owner_uuid'] === $userUuid) {
            return true;
        }
        
        // 2. Check if document is shared with user
        if ($this->isDocumentSharedWithUser($document['id'], $userUuid)) {
            return true;
        }
        
        // 3. Check if user has department-level access
        if ($document['department'] && $this->hasUserDepartmentAccess($userUuid, $document['department'], $permission)) {
            return true;
        }
        
        // 4. Check if user has global permission
        if (PermissionManager::hasPermission($userUuid, 'documents.all', $permission)) {
            return true;
        }
        
        // 5. Check time-based access (if document has expiration)
        if ($document['public_until'] && time() < strtotime($document['public_until'])) {
            return PermissionManager::hasPermission($userUuid, 'documents.public', $permission);
        }
        
        return false;
    }
    
    private function isDocumentSharedWithUser(string $documentId, string $userUuid): bool
    {
        $sharing = $this->db->select('document_shares', ['permission_level'])
            ->where(['document_id' => $documentId, 'user_uuid' => $userUuid, 'is_active' => true])
            ->where('expires_at IS NULL OR expires_at > NOW()')
            ->first();
            
        return !empty($sharing);
    }
    
    private function hasUserDepartmentAccess(string $userUuid, string $department, string $permission): bool
    {
        // Check if user belongs to the department and has required permission
        $userDepartment = $this->userRepo->getUserDepartment($userUuid);
        
        return $userDepartment === $department && 
               PermissionManager::hasPermission($userUuid, "departments.{$department}", $permission);
    }
}
```

### Advanced Model Authorization Patterns

```php
// Hierarchical resource authorization (e.g., team -> project -> task)
class TaskAuthorizationService
{
    public function canAccessTask(string $taskId, string $userUuid, string $permission): bool
    {
        $task = $this->taskRepo->findWithHierarchy($taskId);
        
        if (!$task) {
            return false;
        }
        
        // Check authorization at each level (task -> project -> team)
        $authLevels = [
            "tasks.{$taskId}" => $permission,
            "projects.{$task['project_id']}" => $permission, 
            "teams.{$task['team_id']}" => $permission,
            'tasks.all' => $permission
        ];
        
        foreach ($authLevels as $resource => $requiredPermission) {
            if (PermissionManager::hasPermission($userUuid, $resource, $requiredPermission)) {
                $this->auditAccess($userUuid, $resource, $requiredPermission, 'granted');
                return true;
            }
        }
        
        $this->auditAccess($userUuid, "tasks.{$taskId}", $permission, 'denied');
        return false;
    }
    
    private function auditAccess(string $userUuid, string $resource, string $permission, string $result): void
    {
        AuditLogger::log('authorization_check', [
            'user_uuid' => $userUuid,
            'resource' => $resource,
            'permission' => $permission,
            'result' => $result,
            'timestamp' => time(),
            'ip_address' => $_SERVER['REMOTE_ADDR'] ?? null
        ]);
    }
}

// Attribute-based authorization
class AttributeBasedAuthorizationService
{
    public function canEditUserProfile(string $targetUserUuid, string $currentUserUuid): bool
    {
        // Self-editing is always allowed
        if ($targetUserUuid === $currentUserUuid) {
            return true;
        }
        
        $targetUser = $this->userRepo->find($targetUserUuid);
        $currentUser = $this->userRepo->find($currentUserUuid);
        
        // Attribute-based checks
        $checks = [
            // HR can edit employees in same department
            function() use ($targetUser, $currentUser) {
                return $currentUser['role'] === 'hr' && 
                       $currentUser['department'] === $targetUser['department'];
            },
            
            // Managers can edit direct reports
            function() use ($targetUserUuid, $currentUserUuid) {
                return $this->isDirectReport($targetUserUuid, $currentUserUuid);
            },
            
            // Admins can edit users with lower privilege levels
            function() use ($targetUser, $currentUser) {
                return $currentUser['privilege_level'] > $targetUser['privilege_level'] &&
                       PermissionManager::hasPermission($currentUser['uuid'], 'users.manage', 'D');
            }
        ];
        
        foreach ($checks as $check) {
            if ($check()) {
                return true;
            }
        }
        
        return false;
    }
    
    private function isDirectReport(string $employeeUuid, string $managerUuid): bool
    {
        $employee = $this->userRepo->find($employeeUuid);
        return $employee['manager_uuid'] === $managerUuid;
    }
}
```

### Model Authorization Middleware

```php
class ModelAuthorizationMiddleware
{
    public function process(Request $request, Closure $next): Response
    {
        $route = $request->attributes->get('_route');
        $resourceId = $request->attributes->get('id');
        $userUuid = $request->attributes->get('user_uuid');
        
        // Extract resource type from route
        if (preg_match('/\/api\/(\w+)\//', $route, $matches)) {
            $resourceType = $matches[1];
            
            // Check model-level authorization
            if (!$this->authorizeModelAccess($resourceType, $resourceId, $userUuid, $request->getMethod())) {
                return Response::forbidden('Insufficient permissions for this resource');
            }
        }
        
        return $next($request);
    }
    
    private function authorizeModelAccess(string $resourceType, ?string $resourceId, string $userUuid, string $method): bool
    {
        $permission = $this->getPermissionFromMethod($method);
        
        // Check resource-specific authorization
        $authService = $this->getAuthorizationService($resourceType);
        
        if ($authService && $resourceId) {
            return $authService->canAccess($resourceId, $userUuid, $permission);
        }
        
        // Fallback to RBAC extension
        $permissionService = container()->get(\Glueful\Extensions\RBAC\Services\PermissionAssignmentService::class);
        return $permissionService->hasPermission($userUuid, $resourceType, $permission);
    }
    
    private function getPermissionFromMethod(string $method): string
    {
        return match($method) {
            'GET' => 'view',      // View/Read access
            'POST' => 'create',   // Create new resources
            'PUT', 'PATCH' => 'edit',  // Edit/Update existing resources
            'DELETE' => 'delete', // Delete resources
            default => 'view'
        };
    }
}
```

## Permission Inheritance

Glueful's permission system supports inheritance through role hierarchies with advanced features:

```php
// Create parent role
$roleRepo = container()->get(RoleRepository::class);
$adminRole = $roleRepo->createRole([
    'name' => 'admin',
    'slug' => 'admin',
    'description' => 'Administrator role',
    'level' => 3,
    'status' => 'active'
]);

// Create child role with parent reference
$contentAdminRole = $roleRepo->createRole([
    'name' => 'content_admin',
    'slug' => 'content-admin',
    'description' => 'Content administrator',
    'parent_uuid' => $adminRole->getUuid(),
    'level' => 2,
    'status' => 'active'
]);

// Check inheritance chain
$inheritanceChain = $roleRepo->getRoleHierarchy($contentAdminRole->getUuid());
/*
Returns:
[
    'content_admin' => [
        'uuid' => 'content-admin-uuid',
        'name' => 'content_admin',
        'parent_uuid' => 'admin-uuid'
    ],
    'admin' => [
        'uuid' => 'admin-uuid', 
        'name' => 'admin',
        'parent_uuid' => null
    ]
]
*/

// Get effective permissions (inherited + direct)
$effectivePermissions = $permissionRepo->getEffectivePermissions($userUuid);

// Override parent permissions (more restrictive child role)
$rolePermissionRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\RolePermissionRepository::class);
$rolePermissionRepo->assignPermissions($contentAdminRole->getUuid(), [
    'resource' => 'users',
    'permissions' => ['view', 'edit'], // Only view and edit users, not create or delete
    'scope' => 'departmental',
    'override_inherited' => true // Override parent permissions for this resource
]);
```

### Advanced Inheritance Patterns

```php
// Conditional inheritance based on context
class ConditionalPermissionService
{
    public function hasPermissionWithContext(string $userUuid, string $resource, string $permission, array $context = []): bool
    {
        // Check base permissions first
        $hasBasePermission = PermissionManager::hasPermission($userUuid, $resource, $permission);
        
        if (!$hasBasePermission) {
            return false;
        }
        
        // Apply contextual restrictions
        return $this->checkContextualRestrictions($userUuid, $resource, $permission, $context);
    }
    
    private function checkContextualRestrictions(string $userUuid, string $resource, string $permission, array $context): bool
    {
        // Time-based restrictions
        if (isset($context['time'])) {
            $allowedHours = $this->getUserAllowedHours($userUuid);
            $currentHour = (int)date('H');
            
            if (!in_array($currentHour, $allowedHours)) {
                return false;
            }
        }
        
        // Location-based restrictions
        if (isset($context['ip_address'])) {
            $allowedNetworks = $this->getUserAllowedNetworks($userUuid);
            
            if (!$this->isIpInAllowedNetworks($context['ip_address'], $allowedNetworks)) {
                return false;
            }
        }
        
        // Resource quantity restrictions
        if (isset($context['quantity']) && $permission === 'B') {
            $maxQuantity = $this->getUserMaxQuantity($userUuid, $resource);
            
            if ($context['quantity'] > $maxQuantity) {
                return false;
            }
        }
        
        return true;
    }
}
```

Child roles inherit all permissions from their parent roles, while allowing for additional specific permissions and contextual restrictions.

## Best Practices

For effective permission management:

### 1. **Role-Based Assignment**
Assign permissions to roles rather than individual users:

```php
// Good: Assign to role
$rolePermissionRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\RolePermissionRepository::class);
$userRoleRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\UserRoleRepository::class);

$rolePermissionRepo->assignPermissions($editorRoleUuid, [
    'resource' => 'articles',
    'permissions' => ['view', 'create', 'edit'],
    'scope' => 'owned'
]);
$userRoleRepo->assignRole($userUuid, $editorRoleUuid);

// Avoid: Direct user permissions (use sparingly for exceptions)
$userPermissionRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\UserPermissionRepository::class);
$userPermissionRepo->assignPermissions($userUuid, [
    'resource' => 'articles',
    'permissions' => ['view', 'create', 'edit'],
    'scope' => 'owned'
]);
```

### 2. **Least Privilege Principle**
Give users only the permissions they need:

```php
// Create focused roles with minimal permissions
$roleRepo = container()->get(RoleRepository::class);
$rolePermissionRepo = container()->get(\Glueful\Extensions\RBAC\Repositories\RolePermissionRepository::class);

$viewerRole = $roleRepo->createRole([
    'name' => 'content_viewer',
    'slug' => 'content-viewer',
    'description' => 'Can only view content',
    'level' => 1,
    'status' => 'active'
]);

$rolePermissionRepo->assignPermissions($viewerRole->getUuid(), [
    'resource' => 'articles',
    'permissions' => ['view'], // View only
    'scope' => 'global'
]);

// Gradually add permissions as needed
$rolePermissionRepo->assignPermissions($viewerRole->getUuid(), [
    'resource' => 'categories',
    'permissions' => ['view'],
    'scope' => 'global'
]);
```

### 3. **Permission Testing and Validation**
Test permissions thoroughly:

```php
// Unit test permission logic
class PermissionTest extends TestCase
{
    public function testUserCanEditOwnContent()
    {
        $user = $this->createUser(['role' => 'editor']);
        $article = $this->createArticle(['author_uuid' => $user['uuid']]);
        
        $this->assertTrue(
            $this->documentService->canAccessDocument($article, $user['uuid'], 'D')
        );
    }
    
    public function testUserCannotEditOthersContent()
    {
        $user = $this->createUser(['role' => 'editor']);
        $article = $this->createArticle(['author_uuid' => 'other-user']);
        
        $this->assertFalse(
            $this->documentService->canAccessDocument($article, $user['uuid'], 'D')
        );
    }
}
```

Optimize permission checks:

```php

$permissions = $permissionService->getUserEffectivePermissions($userUuid, $useCache = true);
```

### 7. **Security Guidelines**
- **Use Middleware**: Protect routes with permission middleware
- **Validate at Multiple Layers**: API, service, and data access layers
- **Log Permission Changes**: Track all permission modifications
- **Regular Reviews**: Conduct quarterly permission audits
- **Emergency Procedures**: Have processes for rapid permission revocation
- **Testing**: Include permission tests in your CI/CD pipeline
