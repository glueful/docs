# Events & Listeners

Events decouple side effects (email, logging, analytics) from core domain actions. Glueful provides a PSR‑14 compliant dispatcher plus a lightweight facade (`Glueful\\Events\\Event`) for ergonomic usage.

## When to Emit an Event
Emit events when multiple subsystems may react, or when you want to avoid direct service coupling. Prefer direct method calls if only one consumer will ever exist.

## Configuration Snapshot
`config/events.php`:
```php
return [
  'enabled' => env('EVENTS_ENABLED', true),
  'listeners' => [
    'cache_invalidation' => env('EVENTS_CACHE_INVALIDATION', true),
    'security_monitoring' => env('EVENTS_SECURITY_MONITORING', true),
    'performance_monitoring' => env('EVENTS_PERFORMANCE_MONITORING', true),
    'audit_logging' => env('EVENTS_AUDIT_LOGGING', true),
  ],
  'debug' => env('EVENTS_DEBUG', env('APP_DEBUG', false)),
  'performance' => [
    'enabled' => env('EVENTS_PERFORMANCE_TRACKING', true),
    'slow_threshold_ms' => env('EVENTS_SLOW_THRESHOLD', 100),
    'memory_threshold_mb' => env('EVENTS_MEMORY_THRESHOLD', 10),
  ],
  'extensions' => [
    'enabled' => env('EVENTS_EXTENSIONS_ENABLED', true),
    'auto_register' => env('EVENTS_EXTENSIONS_AUTO_REGISTER', true),
  ],
];
```

## Core Concepts
| Concept | Summary | Benefit |
|---------|---------|---------|
| Event Object | Immutable data record | Clear contract & testability |
| Listener | Callable/subscriber reacting to event | Separation of concerns |
| Facade (`Event::dispatch`) | Ergonomic dispatch entry point | Simplicity |
| Subscriber | Class mapping many events | Organized registration |
| Propagation Stop | `stopPropagation()` method | Early exit optimization |
| Performance Tracking | Slow/memory thresholds | Detect regressions |

## Defining an Event
```php
namespace App\Events;

use Glueful\Events\Contracts\BaseEvent;

class UserRegisteredEvent extends BaseEvent
{
  public function __construct(
    public readonly int $userId,
    public readonly string $email
  ) {
    parent::__construct();
    $this->setMetadata('source', 'auth');
  }
}
```

## Registering a Listener
```php
use Glueful\Events\Event;
use App\Events\UserRegisteredEvent;

Event::listen(UserRegisteredEvent::class, function(UserRegisteredEvent $e) {
  // enqueue welcome email job or increment metric
});
```

## Dispatching
```php
use Glueful\Events\Event;
Event::dispatch(new UserRegisteredEvent($userId, $email));
```

## Subscriber Pattern
```php
namespace App\Listeners;

use Glueful\Events\SubscriberInterface; // assuming interface exists
use App\Events\UserRegisteredEvent;

class UserLifecycleSubscriber implements SubscriberInterface
{
   public static function getSubscribedEvents(): array
   {
     return [
       UserRegisteredEvent::class => 'onRegistered',
     ];
   }

   public function onRegistered(UserRegisteredEvent $e): void
   {
     // handle
   }
}
```

::: tip
Keep event payloads minimal—prefer identifiers over large hydrated models to reduce serialization and memory pressure.
:::

::: warning
Do not perform slow network I/O directly inside listeners; enqueue a job instead. Long listeners hide latency and block other listeners.
:::

## Asynchronous Fan‑Out
Combine events + queues: listener enqueues multiple downstream jobs for email, analytics, or indexing.

## Performance Monitoring
Enable `EVENTS_PERFORMANCE_TRACKING` to log events exceeding `EVENTS_SLOW_THRESHOLD` ms or memory overages; optimize or offload those listeners.

## Built-in Events & Core Listeners

Glueful ships with a focused set of framework events that expose important lifecycle and infrastructure transitions. Use them for observability, security auditing, cache strategy, or extension integration—avoid coupling core business logic directly to these unless necessary.

### Event Catalog

| Category | Event Class | Purpose / When Fired | Typical Listener Use |
|----------|-------------|----------------------|----------------------|
| HTTP | `Glueful\Events\Http\RequestEvent` | Incoming request accepted (early) | Start request metrics, correlation IDs |
| HTTP | `Glueful\Events\Http\ResponseEvent` | Response about to be sent | Log status codes, size metrics |
| HTTP | `Glueful\Events\Http\ExceptionEvent` | Unhandled exception bubbled to handler | Error telemetry, fallback responses |
| HTTP Auth | `Glueful\Events\Http\HttpAuthSuccessEvent` | HTTP auth succeeded | Security audit trail, adaptive session tuning |
| HTTP Auth | `Glueful\Events\Http\HttpAuthFailureEvent` | HTTP auth failed | Increment auth failure metrics, lockout heuristics |
| HTTP Client | `Glueful\Events\Http\HttpClientFailureEvent` | Outbound HTTP client failure | Circuit breaker metrics, retry scheduling |
| Auth | `Glueful\Events\Auth\AuthenticationFailedEvent` | Credential or token authentication failure | Alerting, anomaly detection |
| Auth | `Glueful\Events\Auth\SessionCreatedEvent` | New session issued | Session inventory, geo tracking |
| Auth | `Glueful\Events\Auth\SessionDestroyedEvent` | Session invalidated / logout | Session revocation propagation |
| Auth / Rate Limiting | `Glueful\Events\Auth\RateLimitExceededEvent` | A rate limit bucket exceeded | Notify user, greylist heuristics |
| Security | `Glueful\Events\Security\CSRFViolationEvent` | CSRF validation failed | Security logging, automated blocking |
| Security | `Glueful\Events\Security\AdminAccessEvent` | Admin panel/page accessed | High‑value audit trail |
| Security | `Glueful\Events\Security\AdminSecurityViolationEvent` | Suspicious admin action | Escalation / alerting |
| Cache | `Glueful\Events\Cache\CacheHitEvent` | Cache item resolved from store | Hit/Miss ratio metrics |
| Cache | `Glueful\Events\Cache\CacheMissEvent` | Cache lookup missed | Warm strategies, adaptive TTL tuning |
| Cache | `Glueful\Events\Cache\CacheInvalidatedEvent` | Tag/pattern invalidation executed | Downstream purge (edge/CDN) |
| Database | `Glueful\Events\Database\QueryExecutedEvent` | SQL query executed (with timing) | Slow query logging, metrics |
| Database | `Glueful\Events\Database\EntityCreatedEvent` | Entity persisted first time | Projection/materialized view updates |
| Database | `Glueful\Events\Database\EntityUpdatedEvent` | Existing entity updated | Search index update, cache refresh |
| Webhook | `Glueful\Events\Webhook\WebhookDeliveredEvent` | Outbound webhook delivered | Delivery metrics, completion fan‑out |
| Webhook | `Glueful\Events\Webhook\WebhookFailedEvent` | Outbound webhook exhausted retries | Dead letter handling, operator alert |
| Notifications | `Glueful\Notifications\Events\NotificationQueued` | Notification enqueued for processing | Queue sizing, fan‑out |
| Notifications | `Glueful\Notifications\Events\NotificationScheduled` | Scheduled for future dispatch | Scheduling dashboard |
| Notifications | `Glueful\Notifications\Events\NotificationRetry` | Retry attempt triggered | Backoff visibility |
| Notifications | `Glueful\Notifications\Events\NotificationSent` | Channel send initiated | Per‑channel throughput |
| Notifications | `Glueful\Notifications\Events\NotificationDelivered` | Delivery confirmed (channel level) | User engagement metrics |
| Notifications | `Glueful\Notifications\Events\NotificationFailed` | Final failure (no more retries) | Dead letter / fallback channel |
| Notifications | `Glueful\Notifications\Events\NotificationRead` | User read/consumed notification | Read rate analytics |

### Core Built-in Listeners / Subscribers

| Listener / Subscriber | Type | Listens To (subset) | Purpose |
|-----------------------|------|---------------------|---------|
| `CacheInvalidationListener` | Subscriber | Cache + Entity events | Coordinates cascading cache/tag invalidations |
| `SecurityMonitoringListener` | Listener | Auth & Security events | Centralized security & anomaly telemetry |
| `PerformanceMonitoringListener` | Listener | All events (filtered) | Timing & slow listener diagnostics (when performance tracking enabled) |
| `EmailNotificationListener` (extension) | Listener | Notification events | Queue + channel orchestration & lifecycle handling |

These are auto-registered when the corresponding feature / extension is enabled in configuration. You can disable or replace them via `config/events.php` (`listeners` map) or extension config keys.

> Tip: Keep your own domain listeners narrowly scoped. If you find a listener branching on many event types, split it into targeted listeners or a subscriber implementing an `EventSubscriberInterface` map.

### Extension & Channel Events

The notification system itself emits the notification lifecycle events (see Notifications guide) enabling other extensions (e.g., analytics, auditing, push channels) to subscribe without modifying email logic.

Proceed to the [Notifications guide](/guides/core-services/notifications) for installation & usage of the email channel and patterns for adding new channels.
