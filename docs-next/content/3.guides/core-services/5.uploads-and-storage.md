# Uploads & Storage

This guide covers how Glueful manages file uploads and persistent storage across local and cloud disks. You will learn how to configure disks, safely accept uploads, generate (optionally signed) URLs, and apply security controls (path guarding, MIME validation, size limits, and cleanup strategies).

At a high level:
- `StorageManager` centralizes disk creation via Flysystem adapters (local, memory, S3, Azure, GCS).
- `PathGuard` enforces path safety (no traversal, null bytes, length caps, absolute path blocking by default).
- `UrlGenerator` constructs public or CDN-backed URLs using disk `base_url` / `cdn_base_url`.
- `FileUploader` provides higher-level upload processing, validation, and persistence of file metadata to a repository (`BlobRepository`).
- Config lives in `framework/config/storage.php` and `framework/config/filesystem.php` for security and finder behaviors.

## Core Concepts (At a Glance)
| Concept | Class / Config | Responsibility | Key Methods / Notes |
|---------|----------------|----------------|---------------------|
| Disk | `storage.disks[*]` | Adapter definition + base / CDN URLs | Name resolves to Flysystem operator |
| Storage Manager | `StorageManager` | Disk resolution + helper ops | `disk()`, `putStream()`, `getJson()`, `listContents()` |
| Path Guard | `PathGuard` | Path normalization & safety | `validate($path)`, throws `InvalidArgumentException` |
| URL Generator | `UrlGenerator` | Build public / CDN URLs | `url($path, $disk)` |
| Uploader | `FileUploader` | Validate + persist uploads | `handleUpload()`, `handleBase64Upload()` |
| Metadata Repo | `BlobRepository` (internal usage) | Persist logical file metadata | `create()`, lookup by UUID |
| Signed URL Policy | Disk config (`signed_urls`, `signed_ttl`) | Control presigned issuance | Fallback to plain URL when unsupported |
| Finder Integration | `filesystem.php` config + Symfony Finder | Discovery / maintenance tasks | Used indirectly (cleanup, reports) |

## Quick Start
Minimal controller-style flow handling a single file field named `file`:

```php
use Glueful\Uploader\FileUploader;
use Glueful\Storage\StorageManager;
use Glueful\Storage\Support\UrlGenerator;

public function uploadAction($request)
{
  $uploader = app(FileUploader::class);
  $result = $uploader->handleUpload(
    token: $request->get('token'),
    getParams: $request->query->all(),
    fileParams: $request->files->all() // Symfony shape acceptable
  );

  if (isset($result['error'])) {
    return response()->json($result, 422);
  }

  $urls = app(UrlGenerator::class);
  return response()->json([
    'uuid' => $result['uuid'],
    'path' => $result['path'],
    'url'  => $urls->url($result['path'])
  ], 201);
}
```

> Need asynchronous antivirus or image processing? Offload via the **Queues & Jobs** system and emit events (see Events & Listeners) once future upload events land.

## 1. Disk Configuration
Location: `framework/config/storage.php`

```php
return [
  'default' => env('STORAGE_DEFAULT_DISK', env('STORAGE_DRIVER', 'uploads')),
  'disks' => [
    'uploads' => [
      'driver' => 'local',
      'root' => config('app.paths.uploads'),
      'visibility' => 'private',
      'base_url' => config('app.urls.cdn'), // Used for public URL generation
    ],
    's3' => [
      'driver' => 's3',
      'key' => env('S3_ACCESS_KEY_ID'),
      'secret' => env('S3_SECRET_ACCESS_KEY'),
      'region' => env('S3_REGION', 'us-east-1'),
      'bucket' => env('S3_BUCKET'),
      'endpoint' => env('S3_ENDPOINT'),
      'use_path_style_endpoint' => true,
      'acl' => env('S3_ACL', 'private'),
      'signed_urls' => env('S3_SIGNED_URLS', true),
      'signed_ttl' => (int) env('S3_SIGNED_URL_TTL', 3600),
      'cdn_base_url' => env('S3_CDN_BASE_URL'),
    ],
  ],
];
```

### 1.1 Supported Drivers
- `local`: Stores files on the filesystem path defined by `root`.
- `memory`: Ephemeral in-memory adapter (good for tests).
- `s3`: AWS S3 or compatible (MinIO, DigitalOcean Spaces) via `league/flysystem-aws-s3-v3`.
- `azure`: Azure Blob Storage (requires adapter install and connection string).
- `gcs`: Google Cloud Storage (requires key file or application default credentials).

Each cloud driver is only available if its Flysystem adapter and the underlying SDK classes are installed. Missing dependencies raise configuration exceptions at runtime.

### 1.2 Environment Variables (Common)
| Variable | Purpose |
|----------|---------|
| `STORAGE_DEFAULT_DISK` | Overrides default disk. |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | Credentials for S3-compatible storage. |
| `S3_BUCKET` / `S3_REGION` | Bucket name and region. |
| `S3_ENDPOINT` | Custom endpoint (e.g. MinIO). |
| `S3_CDN_BASE_URL` | CDN or public base used for URL rewriting. |
| `S3_SIGNED_URL_TTL` | Default validity (seconds) for presigned URLs. |
| `UPLOADS_PATH` | Physical path for local `uploads` root. |
| `APP_URL` / `CDN_URL` | Often feed into `app.urls.*` used by `base_url`. |

## 2. Core Services
### 2.1 StorageManager
Retrieval:
```php
use Glueful\Storage\StorageManager;
$storage = app(StorageManager::class);
$disk = $storage->disk();               // default
$s3 = $storage->disk('s3');             // explicit disk
```

Key responsibilities:
- Lazy constructs adapter instances per named disk.
- Provides helper methods: `putJson()`, `getJson()`, `putStream()`, `listContents()` with consistent error translation to `StorageException`.
- Validates paths through `PathGuard` before operations.

### 2.2 PathGuard
Guards against path traversal, null bytes, overly long paths, and (by default) absolute paths.
```php
use Glueful\Storage\PathGuard;
$guard = app(PathGuard::class);
$normalized = $guard->validate('avatars/user123/photo.png');
```
Throws `InvalidArgumentException` on violation.

Failure example:
```php
try {
  app(PathGuard::class)->validate('../etc/passwd');
} catch (\InvalidArgumentException $e) {
  // message e.g. "Path traversal detected"
}
```

### 2.3 UrlGenerator
Generates a public (or CDN) URL if `base_url` / `cdn_base_url` is set for the disk; otherwise returns the path unchanged.
```php
use Glueful\Storage\Support\UrlGenerator;
$urls = app(UrlGenerator::class);
$public = $urls->url('avatars/user123/photo.png', 'uploads');
```

## 3. Upload Workflow (FileUploader)
`FileUploader` encapsulates validation and storage for browser / API initiated uploads.

Steps executed by `handleUpload()`:
1. Validate required request parameters (e.g. `user_id`, token, file array shape).
2. Normalize input (supports native `$_FILES` shape or Symfony `UploadedFile`).
3. Enforce size limits (`filesystem.security.max_upload_size`).
4. Detect MIME using `finfo` and reconcile with extension policy.
5. Validate extension and MIME against configured allow-list or built-in fallback.
6. Optional heuristic scan for hazardous content (`<?php`, `<script`).
7. Generate cryptographically random, timestamped filename.
8. Stream file to disk using atomic temp+move via `putStream()`.
9. Persist metadata via `BlobRepository` (name, mime_type, size, URL, created_by, status).
10. Return a JSON-friendly result containing resource UUID and public URL.

Example minimal controller-style usage:
```php
$uploader = new Glueful\Uploader\FileUploader();
$response = $uploader->handleUpload(
    token: $request->get('token'),
    getParams: $request->query->all(),
    fileParams: $_FILES // or $request->files->all()
);
if (isset($response['error'])) {
    // handle error (HTTP 4xx/5xx)
}
return json_encode($response);
```

### 3.1 Base64 Workflow
Use `handleBase64Upload()` for API clients sending raw base64 payloads:
```php
$tempPath = $uploader->handleBase64Upload($dataUriPayload);
// Then treat $tempPath as the source for further processing or store() operation
```

::callout{type="warning"}
Base64 inflates size by ~33%. Enforce pre-decode maximum lengths and rate limit endpoints accepting base64 to avoid memory spikes.
::

### 3.2 Filename Strategy
Generated format: `<unix_ts>_<16 random hex bytes>[.ext]`. This ensures low collision probability and avoids user-supplied path segments.

### 3.3 Partial Customization
You can override the disk by passing `storageDriver` into the `FileUploader` constructor or customizing `uploadsDirectory` / `cdnBaseUrl` to rewrite base paths for local or S3 disks before fallback instantiation.

## 4. Signed & Public URLs
Use `FlysystemStorage::getSignedUrl()` (via the `StorageInterface`) for S3 disks when credentials are available and `signed_urls` is enabled. Fallback logic returns plain URL on failure or unsupported driver.
```php
$storage = new Glueful\Uploader\Storage\FlysystemStorage($manager, $urls, 's3');
$signed = $storage->getSignedUrl('invoices/2025/receipt.pdf', 900); // 15 min
```
If a disk defines `cdn_base_url`, URLs will prefer it over `base_url`.

Fallback pattern (graceful degradation if signing unsupported):
```php
$manager = app(Glueful\Storage\StorageManager::class);
$urls = app(Glueful\Storage\Support\UrlGenerator::class);
$disk = new Glueful\Uploader\Storage\FlysystemStorage($manager, $urls, 's3');
try {
  $temporary = $disk->getSignedUrl($path, 600);
} catch (\Throwable $e) {
  // Log for observability; fall back to CDN/public URL
  $temporary = $urls->url($path, 's3');
}
```

::callout{type="tip"}
Prefer signed URLs for sensitive or time-scoped assets; use public/CDN URLs for immutable, cacheable assets (e.g. versioned images or docs).
::

## 5. Security Controls
| Control | Source | Purpose |
|---------|--------|---------|
| Path validation | PathGuard | Prevent traversal / absolute paths |
| Extension allow-list | `filesystem.file_manager.allowed_extensions` | Narrow accepted formats |
| MIME verification | `FileUploader::validateFileContent` | Ensure declared type matches real content |
| Size limit | `filesystem.security.max_upload_size` | Prevent resource exhaustion |
| Content scan | `filesystem.security.scan_uploads` | Block rudimentary script/code injection |
| Randomized filenames | `generateSecureFilename` | Avoid collisions & disclosure |
| Atomic writes | `StorageManager::putStream` | Prevent partial file visibility |
| Quarantine (planned) | `filesystem.security.quarantine_suspicious` | Future isolation of suspect files |

### 5.1 Recommendations
- Keep local `uploads` disk `visibility` private; serve via application or signed URLs unless assets are truly public.
- Use separate buckets or prefixes per environment (`dev`, `staging`, `prod`) to avoid accidental cross-use.
- Log and alert on repeated validation failures (rate-limit abusive clients).

### 5.2 Customizing Allowed Extensions
You can constrain which file extensions are accepted globally via the `FILE_ALLOWED_EXTENSIONS` environment variable (a comma-separated list). If unset, the framework falls back to an internal safe default list.

```env
# Allow only common image + PDF documents
FILE_ALLOWED_EXTENSIONS=jpg,jpeg,png,webp,gif,pdf

# Max size (10MB default shown for context)
MAX_FILE_UPLOAD_SIZE=10485760
```

Runtime resolution (from `config/filesystem.php`):
```php
$allowed = config('filesystem.file_manager.allowed_extensions');
// Example: ['jpg','jpeg','png','webp','gif','pdf']
```

Programmatic check (advanced customization):
```php
use Glueful\Uploader\FileUploader;

$uploader = app(FileUploader::class);
$result = $uploader->handleUpload(
  token: $request->get('token'),
  getParams: $request->query->all(),
  fileParams: $request->files->all()
);

if (isset($result['error']) && str_contains($result['error'], 'extension')) {
  // Provide a user-friendly mapping / suggestion
  return response()->json([
    'error' => 'Unsupported file type. Allowed: ' . implode(', ', config('filesystem.file_manager.allowed_extensions') ?? [])
  ], 422);
}
```

::callout{type="tip"}
Maintain the allow‑list as narrowly as possible; prefer enabling new formats only after a security review (e.g. SVG may require sanitization, DOCX macro scanning, etc.).
::

::callout{type="warning"}
Never trust client-supplied filename, MIME type, or extension. Always recompute MIME via `finfo` and validate against an allow‑list (`filesystem.file_manager.allowed_extensions`).
::

::callout{type="info"}
Atomic writes: While local disk writes are effectively atomic with temp + move, some remote object stores may briefly expose partially written objects if you bypass `putStream()`. Always stream to a temp key then move/commit via framework helpers.
::

## 6. Listing & Discovery
Use `StorageManager::listContents($path, $recursive)` for cloud/backends needing enumeration. For richer filtering or large local trees, rely on the injected `FileFinder` service (Symfony Finder) surfaced indirectly through other services (e.g., report generation or cleanup utilities).

## 7. Cleanup & Maintenance
`FileUploader` exposes:
- `getDirectoryStats($dir)` – count, total size, type distribution.
- `cleanupOldFiles($dir, $maxAgeSeconds)` – removes files older than cutoff and returns freed space metrics.

Strategy tips:
- Schedule periodic cleanup for temp or transient upload holding areas.
- Derive retention windows based on business domain (e.g. delete abandoned drafts after 30 days).
- Consider checksum (`calculateChecksum`) storage for deduplication or integrity verification.

### 7.1 Retention Classes
| Class | Example Data | Typical Retention | Notes |
|-------|--------------|-------------------|-------|
| Transient | temp chunks, staging uploads | < 24h | Auto purge cron/queue job |
| User Content | avatars, documents | Business policy (30–365d) | Soft-delete metadata first |
| Compliance / Audit | invoices, signed contracts | Regulatory (years) | Use versioning + WORM if required |

### 7.2 Metrics to Track
- Upload throughput (files/minute, bytes/minute)
- Reject reasons (MIME mismatch, size, extension)
- Average file size distribution (p50/p95)
- Signed URL generation latency & error rate
- Cleanup reclaimed bytes per run

Forward-plan to emit events (`FileUploaded`, `FileUploadRejected`) and feed Observability dashboards.

## 8. Testing Strategies
- Use the `memory` or a temporary local disk for fast unit tests.
- Mock `BlobRepository` to avoid database writes while asserting metadata shape.
- For S3 logic (signed URLs) guard tests with `class_exists('Aws\\S3\\S3Client')` to skip when SDK not installed.
- Validate rejection paths (oversized file, disallowed extension, MIME mismatch) individually.

## 9. Extending Storage
Create custom disks or adapters by adding entries to `storage.php` and ensuring the corresponding adapter classes are autoloadable. For platforms without Flysystem adapters, write a small wrapper returning a `FilesystemOperator` implementation or contribute a new adapter.

To add advanced features:
- Transparent encryption layer: wrap streams before `putStream`.
- Virus scanning: integrate with ClamAV or commercial API before final write.
- Multi-region replication: on successful write, enqueue replication job to secondary disks.

::callout{type="tip"}
Custom adapter? Register its factory in the service container and reference by name in `storage.disks`. Align interface with Flysystem's `FilesystemOperator`.
::

## 10. Common Pitfalls
| Issue | Cause | Resolution |
|-------|-------|-----------|
| `Disk 'x' is not configured` | Name not present in `storage.disks` | Add disk entry; verify env references |
| Plain path returned | No `base_url` / `cdn_base_url` configured | Add `base_url` or CDN URL to disk config |
| Signed URL == plain URL | Driver doesn’t support signing or disabled | Enable `signed_urls` + install adapter/SDK |
| MIME mismatch | User-tampered file or wrong extension | Recompute MIME, reject or normalize extension |
| Partial / truncated file | Bypassing streaming atomic write | Always use `putStream()`; avoid manual fopen+write |
| Memory spike on upload | Large base64 payload decoded in memory | Stream uploads; limit base64 endpoints |
| Slow listing on deep trees | Recursive enumeration on large disk | Use pagination / prefix scoping; offload to background task |
| High duplicate storage | Same file uploaded repeatedly | Store checksum & dedupe on match |
| 413 / entity too large | PHP `post_max_size` / `upload_max_filesize` too low | Increase ini values & framework max size |
| Unexpected public exposure | Mis-set disk `visibility` | Keep private + serve through app / signed URLs |

## 11. Minimal End-to-End Example
```php
use Glueful\Storage\StorageManager;
use Glueful\Storage\Support\UrlGenerator;
use Glueful\Uploader\FileUploader;

// Upload handling (controller)
$uploader = new FileUploader();
$result = $uploader->handleUpload($token, $_GET, $_FILES);
if (!isset($result['error'])) {
    echo 'Stored as ' . $result['url'];
}

// Later: read JSON metadata file stored on a disk
$storage = app(StorageManager::class);
$storage->putJson('profiles/user123.json', ['name' => 'Jane']);
$profile = $storage->getJson('profiles/user123.json');

// Generate a URL (CDN if configured)
$urls = app(UrlGenerator::class);
echo $urls->url('avatars/user123.png');
```

## 13. Large Files & Performance (NEW)
Key considerations when handling large (100MB+) or high-volume uploads:
| Concern | Strategy |
|---------|----------|
| PHP memory limits | Stream to disk; avoid reading entire file into memory |
| PHP ini limits | Align `upload_max_filesize`, `post_max_size`, and framework `max_upload_size` |
| Chunked uploads | Roadmap: initiate multi-part (S3) then finalize manifest |
| Slow clients | Enforce request timeout & max upload rate (web server level) |
| Virus scanning | Perform async scan post-write; quarantine until cleared |
| CDN cache correctness | Use versioned object keys (hash prefix) for immutable assets |

## 14. Cross-Service References
- Queues & Jobs: Offload virus scanning, multi-region replication.
- Events & Listeners: Future upload events (success/failure) for metrics.
- Notifications: Alert on repeated malicious upload attempts.
- Observability: Track latency, failure rate, size distribution.

---
**Summary:** Use `StorageManager` + `FileUploader` for a secure, adapter-agnostic upload pipeline. Enforce strict validation early, leverage atomic writes, and layer CDN/public delivery through `UrlGenerator` or signed URLs where appropriate.
