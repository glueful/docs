# Queues & Jobs

Offload slow or parallelizable work from the request path: email, report generation, image/video processing, cache warmups, webhooks, bulk imports. Glueful's queue system supports database and Redis drivers, delayed jobs, bulk/batch inserts, priority ordering, auto-scaling workers, and structured monitoring.

## When to Use a Job
Use a job when an operation is: latency sensitive to users, CPU / IO intensive, retry-friendly, or fan-out oriented. Keep the API response quick; defer side effects.

## Core Concepts
| Concept | Summary | Benefit |
|---------|---------|---------|
| Job Class | Encapsulated work unit (data + handle method) | Serialization + retry semantics |
| Queue | Named FIFO / priority channel | Work isolation (emails vs critical) |
| Delayed Job | Scheduled for future availability | Time-based orchestration |
| Retry Attempts | Automatic re-execution on failure | Transient fault resilience |
| Backoff Strategy | Delay growth between retries | Reduces pressure on failing systems |
| Dead Letter / Failed Table | Terminal failure capture | Post-mortem + replay |
| Batch / Bulk Push | Insert multiple jobs efficiently | High throughput ingest |

## Configuration
`config/queue.php` defines `default`, `connections.*`, `failed.*`, `workers.*`, and monitoring thresholds. Tune `retry_after` to exceed max expected processing time of normal jobs.

## Minimal Job Example
```php
namespace App\Jobs;

use Glueful\Queue\Jobs\Job; // Assuming base Job class

class SendWelcomeEmailJob extends Job
{
    public function __construct(
        private int $userId
    ) {}

    public function handle(): void
    {
        // look up user & send email
    }
}
```

## Dispatching
```php
use Glueful\Queue\QueueManager;
use App\Jobs\SendWelcomeEmailJob;

$queue = service(QueueManager::class);
$queue->push(new SendWelcomeEmailJob($userId));
```

## Delayed & Prioritized Jobs
```php
$queue->later(300, new RecalculateMetricsJob($accountId)); // 5 minutes
$queue->push(new CriticalPaymentJob($payload), 'payments_high'); // dedicated queue
```

## Bulk Insertion
```php
$payloads = array_map(fn($id) => new WarmUserCacheJob($id), $userIds);
$queue->bulk($payloads, queue: 'warmups');
```

## Idempotency Pattern
```php
class GenerateInvoicePdfJob extends Job
{
    public function handle(): void
    {
        if ($this->alreadyGenerated($this->invoiceId)) {
            return; // safe no-op; prevents duplicates on retry
        }
        $pdf = $this->builder->create($this->invoiceId);
        $this->store($pdf);
    }
}
```

::: tip
Make jobs tiny and composable. A long “god job” that performs dozens of steps is harder to retry, resume, or parallelize.
:::

::: warning
Never swallow exceptions silently—throwing signals the queue system to retry or mark failed. Logging without throw hides operational issues.
:::

## Failure & Retry
Retries are governed by configuration and internal attempt count. Implement exponential backoff by encoding delay logic in job metadata or using a wrapper strategy.

## Monitoring
Track: queue depth, avg processing time, failures per minute, retry ratio, age of oldest job. Spikes in oldest age indicate starvation or insufficient workers.

## Graceful Degradation
For non-critical tasks (analytics enrichment), consider dropping or sampling under extreme backlog to preserve critical throughput.

## Common Patterns
| Pattern | Description | Benefit |
|---------|-------------|---------|
| Fan-out via Events | Domain event dispatch -> listeners enqueue jobs | Decouple write path |
| Warm-on-Write | After create/update, enqueue cache warm job | Faster subsequent reads |
| Batch Aggregator | Multiple small events coalesced into one job | Reduced overhead |
| Dead Letter Replay | Periodic scan & requeue certain failures | Operational recovery |

### Queue-Specific Issues
| Symptom | Cause | Action |
|---------|-------|--------|
| Backlog growing | Insufficient workers / slow handlers | Scale workers, profile heavy jobs |
| High failure rate | Non-idempotent side effects | Add idempotency keys, external transaction checks |
| Stale delayed jobs | Clock skew across nodes | NTP sync & consistent time source |
| Priority inversion | All jobs on same queue | Split into dedicated queues per criticality |
