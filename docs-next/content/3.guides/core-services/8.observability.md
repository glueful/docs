# Observability & Telemetry

Build a disciplined signal layer: high-fidelity structured logs now; safe extension points for metrics & tracing later—without rewriting your code.

> Status: Logging is implemented. Tracing & metrics config keys exist but no runtime instrumentation currently ships. This guide shows how to prepare code so future adoption (OpenTelemetry, Datadog, New Relic) is mostly configuration-only.

## At a Glance

- Structured separation of framework vs application logs (`logging.php`).
- Channelized daily rotating files with environment-driven levels.
- Performance signal surfacing: slow requests, slow DB queries, slow outbound HTTP.
- Planned (not yet implemented): distributed tracing, span context propagation, custom counters/histograms.
- Safe future migration path: wrap your business logging in lightweight helpers now.
- Cross-links: see `6.scheduling.md` (scheduler run visibility), `7.distributed-locks.md` (lock contention), uploads guide (large file performance), events/notifications guide (emittable lifecycle signals).

## Quick Start

1. Confirm logging enabled:
   - Framework: `FRAMEWORK_LOGGING_ENABLED=true`
   - App: `LOG_TO_FILE=true`
2. Set environment-aligned levels:
   - `FRAMEWORK_LOG_LEVEL=info`, `LOG_LEVEL=debug` (local) → escalate to `error` in production.
3. (Optional) Enable performance early warnings:
   - `LOG_SLOW_REQUESTS=true`, `SLOW_REQUEST_THRESHOLD=1200`
   - `LOG_SLOW_QUERIES=true`, `SLOW_QUERY_THRESHOLD=300`
4. Add a correlation ID middleware (until native provided).
5. Wrap custom domain logging with a helper for future trace injection.

### Minimal Correlation Middleware (Example)

```php
// app/Http/Middleware/CorrelationIdMiddleware.php
namespace App\Http\Middleware;

use Closure; use Illuminate\Http\Request; use Ramsey\Uuid\Uuid; // or any UUID lib

class CorrelationIdMiddleware {
	public function handle(Request $request, Closure $next) {
		$header = 'X-Correlation-ID';
		$id = $request->headers->get($header) ?? Uuid::uuid4()->toString();
		// Make available globally (framework-specific container or context strategy)
		app()->instance('correlation_id', $id);
		// Proceed
		$response = $next($request);
		$response->headers->set($header, $id);
		return $response;
	}
}
```

Then register in your HTTP kernel / pipeline. Downstream logs can fetch `app('correlation_id')` and attach it.

### Domain Log Helper

```php
function domain_log(string $message, array $context = []): void {
	$context['correlation_id'] = app('correlation_id') ?? null;
	logger()->channel(env('LOG_CHANNEL', 'app'))->info($message, $context);
}
```

## Logging Architecture

Defined in `logging.php`:

| Layer | Purpose | Toggle | Key Env |
|-------|---------|--------|---------|
| Framework Channel | Protocol + lifecycle + internal errors | `FRAMEWORK_LOGGING_ENABLED` | `FRAMEWORK_LOG_LEVEL` |
| App Channel | Domain/business events | `LOG_TO_FILE` | `LOG_LEVEL` |
| Slow Requests | Warn on latency outliers | `LOG_SLOW_REQUESTS` | `SLOW_REQUEST_THRESHOLD` |
| Slow Queries | Highlight N+1 / missing indexes | `LOG_SLOW_QUERIES` | `SLOW_QUERY_THRESHOLD` |
| HTTP Client Failures | External dependency health | `LOG_HTTP_CLIENT_FAILURES` | `HTTP_CLIENT_SLOW_THRESHOLD` |

Rotation & retention:

| Setting | Env | Meaning |
|---------|-----|---------|
| Strategy | `LOG_ROTATION_STRATEGY` | daily | weekly | monthly | size |
| Days | `LOG_ROTATION_DAYS` | Retention horizon |
| Size Limit | `LOG_MAX_SIZE` | For size-based rotation mode |

### Adding a New Channel

1. Define in `logging.php` under `channels`.
2. Use `logger()->channel('your_channel')->info('something')`.
3. Keep semantic boundaries: avoid mixing framework and domain concerns.

## Preparing for Metrics (Forward-Compatible Pattern)

Because no native metrics API exists yet, isolate potential metric points behind an interface you own.

```php
interface MetricsSink {
	public function increment(string $name, int $by = 1, array $tags = []): void;
	public function observe(string $name, float $value, array $tags = []): void; // for timers/sizes
}

class NullMetricsSink implements MetricsSink {
	public function increment(string $name, int $by = 1, array $tags = []): void {}
	public function observe(string $name, float $value, array $tags = []): void {}
}
```

Bind `NullMetricsSink` today; swap with OpenTelemetry adapter later.

Suggested naming: `domain.action.completed`, `scheduler.job.duration_ms`, `uploads.bytes_processed` (future).

## Tracing Configuration (Stub)

File: `observability.php`

| Key | Meaning | Current Behavior |
|-----|---------|------------------|
| `tracing.enabled` | Master flag | No effect unless custom code reads it |
| `tracing.driver` | `noop|otel|datadog|newrelic` | Only `noop` effectively active |
| `tracing.service_name` | Logical service identifier | For future exporter enrichment |
| `tracing.service_version` | Deployment version tag | For future exporters |
| `tracing.drivers.*` | Driver specific config arrays | Unused now |

### What Happens If You Enable It Now?

Nothing by default. You must create your own service provider to read config and bootstrap a tracer. Example skeleton:

```php
class TracingServiceProvider extends ServiceProvider {
  public function register() {
	if (!config('observability.tracing.enabled')) return;
	// Choose driver & build tracer (OpenTelemetry SDK, Datadog ddtrace, etc.)
	app()->instance('tracer', new NoopTracer());
  }
}
```

Then in code you could:

```php
$tracer = app('tracer');
// $span = $tracer->startSpan('my.operation'); // future
```

## Advanced Patterns

| Pattern | Benefit | Hint |
|---------|---------|------|
| Correlation Chaining | Follow a request through async jobs | Persist correlation ID into queued job payload |
| Semantic Keys | Easier aggregation | Use dot.delimited names (`user.auth.login`) |
| Structured Fail Blocks | Faster root cause | Always log `error_code`, `exception_class`, `correlation_id` |
| Progressive Sampling | Control volume | Sample only debug-level or high-frequency spans in future tracing |

### Recommended Log Field Keys
`correlation_id`, `request_id`, `user_id`, `actor_role`, `job`, `lock_key`, `duration_ms`, `error_code`, `exception_class`, `remote_service`, `payload_size`, `bytes`, `retry`.

## Troubleshooting

| Symptom | Likely Cause | Action |
|---------|-------------|--------|
| Missing correlation IDs | Middleware not registered | Add early in pipeline |
| Slow query warnings noisy | Threshold too low | Tune `SLOW_QUERY_THRESHOLD` |
| Log files huge | Debug level in prod | Set `LOG_LEVEL=error` |
| Duplicate events | Both framework & app log same concern | Clarify responsibility boundary |
| Tracing shows nothing | Tracer not actually bootstrapped | Implement service provider |
