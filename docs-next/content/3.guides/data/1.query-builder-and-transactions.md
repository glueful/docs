# Query Builder & Transactions

Glueful's modular Query Builder orchestrates 14 focused components to produce expressive, safe, and observable SQL. Coupled with the Transaction Manager it supports nested transactions (savepoints) and deadlock retry with exponential backoff.

> Note: All APIs described here are sourced directly from existing classes under `src/Database/*`. If a method name differs in future refactors, update examples accordingly.

## Quick Start

```php
use Glueful\Database\Connection; // or resolve from container

$db = container()->get('database'); // preferred

$users = $db
	->table('users')
	->select(['id','email','created_at'])
	->where(['active' => 1])
	->orderBy(['created_at' => 'DESC'])
	->limit(25)
	->get();
```

## Fluent Operations

| Operation | Method | Notes |
|-----------|--------|-------|
| Table | `table('users')` | Sets base table (alias of `from()`) |
| Select | `select([...])` | Defaults to `*` |
| Where | `where([...])`, `orWhere()` | Array = AND each pair |
| In | `whereIn($col, $values)` | Parameterized list |
| Joins | `join()`, `leftJoin()` | Combine datasets |
| Ordering | `orderBy(['col' => 'ASC'])` | Multiple columns supported |
| Pagination | `limit()`, `offset()` | Prefer keyset for deep pages |
| Aggregates | `count()`, `max()`, etc. (via result processing) | Wrapper methods may exist |
| Raw | `selectRaw()` | Use only with trusted input (see Warning) |

> Warning: Prefer parameter binding over raw string interpolation—`selectRaw()` passes expressions directly.

## Where Clause Patterns

```php
$recent = $db->table('orders')
	->where('created_at', '>=', '2025-01-01')
	->where(function ($q) {
		$q->where(['status' => 'pending']);
		$q->orWhere('status', '=', 'processing');
	})
	->whereIn('channel', ['web','mobile'])
	->get();
```

## Grouped Logic

```php
$complex = $db->table('users')
	->where(function ($q) {
		$q->where('role', '=', 'admin');
		$q->orWhere('role', '=', 'moderator');
	})
	->whereNull('deleted_at')
	->get();
```

> Tip: Encapsulate recurring conditions in local higher‑order functions for reuse across queries.

## Joins & Aliasing

```php
$rows = $db->table('users')
	->select(['users.id','profiles.bio','roles.name AS role'])
	->leftJoin('profiles', 'profiles.user_id', '=', 'users.id')
	->join('user_roles', 'user_roles.user_id', '=', 'users.id')
	->join('roles', 'roles.id', '=', 'user_roles.role_id')
	->where(['users.active' => 1])
	->get();
```

> Warning: Always qualify column names when joining tables that share common column identifiers (e.g. `id`, `created_at`).

## Soft Deletes & Filtering

If soft delete support is enabled via `SoftDeleteHandlerInterface`, deleted rows are automatically excluded until explicitly included (e.g. hypothetical `withTrashed()` method).

## Pagination Strategies

| Strategy | Use Case | Trade‑off |
|----------|----------|-----------|
| Offset/Limit | Simple UI pages | Slow for deep pages (large OFFSET scans) |
| Keyset (Cursor) | Infinite scroll / real-time lists | Requires stable sort column |
| Seek Pagination | Large table exports | Needs indexed monotonic key |

> Tip: Switch to keyset (cursor) pagination after page ~50 or sooner on very large tables.

## Transactions

Transactions are managed by `TransactionManager` with deadlock retries and nested savepoints.

### Basic Usage

```php
$result = $db->transaction(function ($tx) use ($db) {
	$db->table('accounts')->where('id',1)->update(['balance' => 500]);
	$db->table('ledger')->insert(['account_id' => 1, 'delta' => 500]);
	return true;
});
```

### Nested Transactions (Savepoints)

```php
$db->transaction(function () use ($db) {
	$db->transaction(function () use ($db) {
		$db->table('audit')->insert(['event' => 'inner']);
	});
	$db->table('audit')->insert(['event' => 'outer']);
});
```

> Tip: Keep transactions as small as possible—perform expensive reads or external calls before/after the transactional block.

### Deadlock Retry Logic

On detected deadlock the manager rolls back, applies incremental backoff, and retries up to a max (default 3). Tune via a setter or config (future).

> Warning: High deadlock frequency is usually a modeling/indexing issue—profiling should precede simply raising retry counts.

## Query Caching & Optimization

Toggle caching (if supported) and optimization flags for expensive read paths:

```php
$items = $db->table('products')
	->select(['id','name'])
	->where(['active' => 1])
	->cache(ttl: 600)
	->optimize()
	->get();
```

> Note: Invalidate caches on underlying table mutation or enable `QUERY_CACHE_AUTO_INVALIDATE` in config.

## Performance & Safety Checklist

| Item | Rationale |
|------|-----------|
| Parameterize user input | Prevent SQL injection |
| Use keyset pagination for deep lists | Avoid large OFFSET scans |
| Limit selected columns | Reduce I/O and memory footprint |
| Keep transactions short | Lower lock contention |
| Add composite indexes for multi-column filters | Improves selectivity |
| Profile slow queries (`slow_threshold`) | Target actual bottlenecks |

> Tip: Enable development query monitor to surface N+1 and repetitive patterns early.
