# Pagination & Seeding

Efficient pagination keeps list endpoints predictable under growth; disciplined seeding bootstraps environments & tests reproducibly. This guide builds on the Query Builder, Repositories, and Migrations system.

## Pagination Strategies

| Strategy | Query Pattern | Pros | Cons | Use When |
|----------|---------------|------|------|----------|
| Offset/Limit | `OFFSET n LIMIT m` | Simple, ubiquitous | Slow for deep pages (scan cost) | Small datasets, admin UIs |
| Keyset (Cursor) | `WHERE id < :cursor ORDER BY id DESC LIMIT m` | Stable latency, no large skips | Requires monotonic sortable column | Infinite scroll, APIs with deep traversal |
| Seek via Composite | `WHERE (score, id) < (:score,:id)` | Ordered on multi metrics | More complex predicate | Ranking feeds |
| Window (Analytic) | Window functions (future) | Rich calculations | Heavier planning | Aggregated leaderboards (later) |

> Tip: Switch to keyset before offset pages exceed a practical threshold (e.g. page 50) or when p95 latency grows with page depth.

### Selecting a Stable Sort Column

| Column Type | Suitability | Notes |
|-------------|------------|-------|
| Auto‑increment PK | Excellent | Monotonic, indexed |
| UUID | Poor for keyset | Non‑sequential; use timestamp + tie‑breaker |
| Created Timestamp | Good | Add secondary PK ordering for duplicates |
| Updated Timestamp | Unstable | Changes reorder history—avoid for cursor |

> Warning: Using `updated_at` for cursors can cause record duplication or omission as rows move between pages during iteration.

### Implementing Offset Pagination (Repository)

```php
$pageData = $userRepo->paginate(page: 3, perPage: 25, orderBy: ['created_at' => 'DESC']);
```

### Implementing Keyset Pagination

```php
// Assume last seen article id (cursor)
$cursor = $_GET['after'] ?? null;
$limit = 25;

$query = $db->table('articles')
    ->select(['id','title','published_at'])
    ->orderBy(['id' => 'DESC'])
    ->limit($limit);

if ($cursor) {
    $query->where('id', '<', (int)$cursor);
}

$rows = $query->get();
$nextCursor = $rows !== [] ? end($rows)['id'] : null;
```

> Tip: Return cursors (opaque tokens) not raw integer IDs for external APIs; encode with signature/HMAC for tamper resistance.

### Hybrid Approach

Start with offset for simplicity, add dedicated keyset endpoints for heavy scrolling use-cases, and deprecate offset where deep traversal appears in metrics.

## Pagination Metadata

Expose metadata alongside result sets:

```json
{
  "data": [...],
  "pagination": {
    "page": 3,
    "per_page": 25,
    "next_cursor": "178234",
    "has_more": true
  }
}
```

> Note: For cursor pagination, `page` can be omitted; rely on `has_more` + `next_cursor`.

## Seeding Overview

Seed data ensures new environments, test runs, and demos start from a consistent baseline: roles, permissions, feature flags, system configuration, reference lists.

| Seed Type | Location | Characteristics |
|-----------|----------|-----------------|
| Structural Reference | Migration (mixed) | Few rows, stable |
| Large Lookup / Taxonomy | Dedicated seed migration | Many rows, occasionally updated |
| Dynamic Sample (dev only) | Seeder script / console command | Non‑production, re-runnable |
| Bulk Import (one-time) | External ETL + follow-up migration | High volume, auditable |

> Tip: Keep production seed migrations idempotent (check existence before insert) to allow safe reapplication during infra rebuilds.

### Example: Mixed Structural + Seed (Simplified)

```php
class CreateFeatureFlags implements MigrationInterface {
  public function up(SchemaBuilderInterface $schema): void {
    $schema->createTable('feature_flags', function ($t) {
      $t->bigInteger('id')->primary()->autoIncrement();
      $t->string('key',120)->unique();
      $t->boolean('enabled')->default(false);
      $t->timestamp('created_at')->default('CURRENT_TIMESTAMP');
    });

    // seed
    $db = new Connection();
    $db->table('feature_flags')->insertBatch([
      ['key' => 'search.v2','enabled' => false],
      ['key' => 'billing.reconciler','enabled' => true]
    ]);
  }
  public function down(SchemaBuilderInterface $s): void { $s->dropTableIfExists('feature_flags'); }
  public function getDescription(): string { return 'Feature flags table + baseline'; }
}
```

### High Volume Seeding Pattern

1. Create empty tables + essential indexes
2. Disable expensive hooks / foreign key checks if permissible
3. Stream data in chunks (e.g. 1k rows) using `bulkCreate`
4. Re‑enable constraints & build secondary indexes (if delayed)
5. Verify counts & integrity

> Warning: Avoid wrapping huge seed imports in a single transaction; long locks + massive rollback risk. Use chunked commits.

## Idempotent Seed Techniques

| Technique | Example | Use Case |
|-----------|---------|---------|
| Upsert (future) | insert or update on key | Updating reference attributes |
| Existence check | `if (!exists) insert` | Small stable rows |
| Hash comparison | Detect changed dataset | Large taxonomy refresh |

> Tip: Store a dataset version row (e.g. in `seed_metadata`) to short‑circuit expensive reimports when version matches.

## Seeding in Tests

| Practice | Benefit |
|----------|--------|
| Minimal baseline seed | Faster test startup |
| Transaction per test rollback | Isolation without rebuild |
| Deterministic generators | Stable expectations |
| Avoid huge fixtures | Lower memory & parse time |

> Tip: Compose scenario seeds (user with roles + permissions) via repository bulk calls for clarity.

## Performance & Safety Checklist

| Item | Rationale |
|------|-----------|
| Choose keyset for deep scroll | Avoid large OFFSET scans |
| Chunk bulk seeds | Bound memory & lock duration |
| Index pagination sort columns | Prevent full table scans |
| Idempotent seed logic | Safe reapplication |
| Avoid long transactions for imports | Reduce lock contention |
| Encode opaque cursors | Prevent tampering |

> Tip: Monitor API pagination latency histogram after releases adding new list features; regressions often reveal missing indexes.
