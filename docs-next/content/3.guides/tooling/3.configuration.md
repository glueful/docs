# Configuration

Glueful centralizes application behavior in PHP configuration files under `config/`, layered with environment variables. This guide explains how configuration is structured, accessed, overridden, validated, and secured—plus upcoming improvements (caching, schema validation, secrets providers).

## At a Glance

- Flat PHP files returning associative arrays (no runtime side effects).
- Environment overrides via `env()` helper, with smart defaults influenced by `APP_ENV`.
- Path consolidation (`app.paths.*`) prevents scattering filesystem logic.
- Config arrays consumed by services through container build or helper functions (e.g., `config('app.env')`).
- Extensions can ship their own config files merged under namespaced keys (pattern described below).
- Roadmap: immutable compiled config cache for prod, per-key validation rules, secrets manager integration.

## File Structure (Representative)

| File | Purpose | Notable Sections |
|------|---------|------------------|
| `config/app.php` | Core app identity & paths | env/debug toggles, versioning, paths, performance memory monitors |
| `config/database.php` | DB engines & pooling | multi-engine arrays, pooling, query cache policies |
| `config/cache.php` | Cache drivers/stores | stores, distributed, stampede protection, edge rules |
| `config/logging.php` | Framework vs application logging split | channels, rotation, environment-driven levels |
| `config/*.php` (others) | Queues, events, image, permissions, etc. | Domain-specific knobs |

## Loading Order (Conceptual)

1. Base application bootstrap initializes environment variables (`$_ENV`, server, or `.env` loader if present).
2. Container build phase (or config access) executes each `config/*.php` returning arrays.
3. Environment-driven defaults inside config files compute smart values (e.g., production disables docs, forces HTTPS).
4. Extensions (once loaded) contribute additional configuration merged after core (pattern: `config/extension-name.php`).
5. Consumer code retrieves values via helper or injected configuration service.

No on-disk cache yet (see Roadmap). Each request/CLI run loads raw files—fast enough for current scale.

## Environment Variables Strategy

| Variable | Influences | Notes |
|----------|-----------|-------|
| `APP_ENV` | Debug, API docs, HTTPS enforcement, log levels | Primary behavior gate |
| `APP_DEBUG` | Overrides auto debug inference | Use only for local overrides |
| `APP_KEY` | Encryption/security features | Must be set in non-local envs |
| `DB_*` families | Connection engines/pooling | Sensitive; prefer secrets storage |
| `CACHE_DRIVER` | Default cache store | File, redis, memcached, array (test) |
| `LOG_*` | Logging enablement & channels | Production reduces verbosity |

Smart defaults minimize required env surface—only set non-defaults intentionally.

## Accessing Configuration

Two common patterns:

```php
$env = config('app.env');
$defaultTtl = config('cache.ttl');
$mysqlHost = config('database.mysql.host');
```

DI style: inject a service that internally reads config during construction (favors immutability during process lifetime).

Avoid reading config repeatedly in tight loops—store derived values locally.

## Namespacing & Key Conventions

Use dot notation: `domain.subsection.leaf` mapping onto nested arrays. Keep keys lowercase snake_case for consistency. Domain roots (e.g. `app`, `database`, `cache`, `logging`) should remain stable to avoid churn.

## Overriding & Merging

Because config files are plain PHP, overrides happen by adjusting environment variables (preferred) or editing the file. For deployment-specific adjustments avoid patching vendor or framework defaults—add an environment-level overlay file if needed (planned feature: `config/local/*.php` merge stage in Roadmap).

### Extension Configuration

Recommended extension pattern:

```
extensions/your-extension/config/rbac.php
extensions/your-extension/config/notifications.php
```

During extension boot merge arrays into prefixed keys, e.g.: `aegis.rbac.roles`. Avoid collisions by always anchoring under the extension name.

## Paths Centralization

`app.paths` keys in `config/app.php` define authoritative filesystem locations. Always use these rather than re-computing to support future relocations or containerization. Example:

```php
$uploadDir = config('app.paths.uploads');
```

## Security & Secrets

| Concern | Recommendation |
|---------|---------------|
| Sensitive values (DB_PASSWORD, APP_KEY) | Provide via environment / secret manager, never commit |
| Boolean toggles | Always cast `(bool)` in config file when reading `env()` |
| Derived URLs | Sanitize trailing slashes to prevent duplication (`rtrim`) |
| DB SSL | Enable production by default; provide cert paths via environment |
| Cache Prefix | Use distinct `CACHE_PREFIX` per environment to prevent key bleed |

Future integration: dynamic secret resolution via provider (AWS Secrets Manager, Vault) with in-memory refresh schedule.

## Validation Patterns

Currently implicit—code assumes shape. Recommended defensive checks near consumption boundaries:

```php
$threshold = config('app.performance.memory.monitoring.alert_threshold');
if ($threshold <= 0 || $threshold >= 1) {
	throw new \RuntimeException('Memory alert threshold must be between 0 and 1');
}
```

Roadmap introduces structured validation registry (schema-like arrays or attributes) executed once at boot, failing fast with aggregated error reporting.

## Environment-Aware Defaults

Example from `app.php`:

```php
'debug' => (bool) env('APP_DEBUG', env('APP_ENV') !== 'production'),
```

This ensures local/staging default to debug even if env var omitted, while production enforces explicit enabling. Similar pattern used for API docs, HTTPS enforcement, logging verbosity.

## Performance Considerations

Current cost: each config file included per run. Acceptable for now. Optimization techniques (planned):

| Technique | Benefit |
|-----------|---------|
| Compiled config cache (single PHP array) | Fewer filesystem stats & includes |
| Immutable config object | Prevent accidental runtime mutation |
| Pre-flattened key map | Faster lookups for nested keys |
| Warm path resolution | Resolve `base_path` calls once |

## Caching (Roadmap)

Planned `config:cache` command will:

1. Aggregate all core + extension config arrays.
2. Validate shapes & required keys.
3. Serialize to a single optimized PHP file (`bootstrap/cache/config.php`).
4. Switch runtime to load cached file if timestamp newer than sources.
5. Provide `config:clear` to revert.

## Troubleshooting

| Symptom | Likely Cause | Resolution |
|---------|-------------|-----------|
| Missing key returns null | Typo in key or extension not loaded | Check namespace prefix & extension load order |
| Env override ignored | Variable not exported to process | Verify deployment environment export method |
| Unexpected production debug enabled | `APP_DEBUG` explicitly true | Remove or set to false in secret store |
| Cache prefix collision | Shared `CACHE_PREFIX` across envs | Set unique prefix per environment |
| SSL not applied | Missing cert files | Provide `DB_SSL_*` vars and ensure readable paths |

## Best Practices

| Practice | Why |
|----------|-----|
| Prefer env overrides vs editing distributed config | Simplifies upgrades |
| Keep config pure (no network I/O) | Deterministic fast boot |
| Document non-obvious keys inline with comments | Reduces tribal knowledge |
| Co-locate related settings under nested arrays | Easier scoping & iteration |
| Avoid dynamic function calls in tight loops | Prevent per-request overhead |
| Use explicit type casting for env values | Avoid stringly typed booleans/numbers |

## Roadmap

1. Config cache compile & clear commands.
2. Schema/validation registry with aggregated error reporting.
3. Secrets provider abstraction (Vault, AWS, Parameter Store).
4. Hot reload in dev (file watcher triggers container rebuild).
5. Lazy evaluated derived values caching (e.g., prebuilt URL map).
6. Config diff tool (`config:diff --env=production`).

Configuration in Glueful favors clarity: simple PHP arrays, environment-driven flexibility, and centralized paths. Use explicit env overrides, validate critical thresholds, and prepare to adopt the cache & validation enhancements as they land to further harden boot performance and safety.
