# JWT Authentication in 10 Minutes

Glueful comes with a **complete JWT authentication system** built-in! No controllers to create, no routes to define, no migrations to run - everything works out of the box. This tutorial shows you how to use the existing system effectively.

## What's Already Available

Out of the box, Glueful provides:
- ✅ **Complete authentication API** (`/auth/*` endpoints)
- ✅ **User management system** (users table with UUID)
- ✅ **JWT token service** with refresh tokens
- ✅ **Session management** (auth_sessions table)
- ✅ **CRUD API for all tables** (`/{resource}/*` endpoints)
- ✅ **Rate limiting and security** features
- ✅ **Email verification** and password reset

## Prerequisites

- Glueful project setup ([installation guide](../1.start/2.installation.md))
- 5 minutes to test the API
- A REST client (curl, Postman, or similar)

## Understanding the Built-in System

### Pre-built Database Tables

The framework includes these tables automatically:

```sql
-- Users table (UUID-based)
CREATE TABLE users (
    uuid UUID PRIMARY KEY,
    username VARCHAR(255) UNIQUE,
    email VARCHAR(255) UNIQUE,
    password VARCHAR(255),
    status VARCHAR(50) DEFAULT 'active',
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- Auth sessions for token management
CREATE TABLE auth_sessions (
    session_uuid UUID PRIMARY KEY,
    user_uuid UUID REFERENCES users(uuid),
    access_token TEXT,
    refresh_token TEXT,
    access_token_expires_at TIMESTAMP,
    refresh_token_expires_at TIMESTAMP,
    device_fingerprint VARCHAR(255),
    ip_address INET,
    user_agent TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- Plus: scheduled_jobs, notifications, audit_logs, queue_jobs, etc.
```

**No migrations needed!** Everything is ready to use.

### Built-in Authentication Routes

The framework automatically provides these endpoints:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/auth/login` | User login with username/email and password |
| `POST` | `/auth/logout` | Logout and invalidate tokens |
| `POST` | `/auth/refresh-token` | Refresh access token |
| `POST` | `/auth/validate-token` | Validate current token |
| `POST` | `/auth/verify-email` | Send email verification code |
| `POST` | `/auth/verify-otp` | Verify OTP code |
| `POST` | `/auth/forgot-password` | Initiate password reset |
| `POST` | `/auth/reset-password` | Reset password with code |
| `POST` | `/auth/refresh-permissions` | Update user permissions |

### Built-in CRUD API

For **any table**, you automatically get:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/{table}` | List all records (paginated) |
| `GET` | `/{table}/{uuid}` | Get single record by UUID |
| `POST` | `/{table}` | Create new record |
| `PUT` | `/{table}/{uuid}` | Update record by UUID |
| `DELETE` | `/{table}/{uuid}` | Delete record by UUID |

**Example**: Users table becomes `/users`, `/users/{uuid}`, etc.

## Step 1: Test the Authentication System

### 1. Create a User Account (via CRUD API)

Since user registration might not be publicly available, let's create a user directly:

```bash
curl -X POST http://localhost:8000/users \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "email": "test@example.com", 
    "password": "securepassword123",
    "status": "active"
  }'
```

**Note**: In production, you'd typically use a registration endpoint or admin interface.

### 2. Login and Get JWT Token

```bash
curl -X POST http://localhost:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "test@example.com",
    "password": "securepassword123"
  }'
```

**Response:**

### 3. Use Token to Access Protected Resources

```bash
# Get all users (requires authentication)

  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..."
```


### 4. Refresh Your Token

```bash
curl -X POST http://localhost:8000/auth/refresh-token \
  -H "Content-Type: application/json" \
  -d '{
    "refresh_token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..."
```

### 5. Validate Token

```bash
curl -X POST http://localhost:8000/auth/validate-token \
  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..."
```

### 6. Logout

```bash
curl -X POST http://localhost:8000/auth/logout \
```

## Step 4: Configuration (Optional)

If you want to customize JWT settings, edit `config/session.php`:

```php
<?php

return [
    // JWT Configuration
    'jwt_key' => env('JWT_SECRET', 'your-secret-key'),
    'access_token_lifetime' => env('JWT_ACCESS_TOKEN_LIFETIME', 900), // 15 minutes
    'refresh_token_lifetime' => env('JWT_REFRESH_TOKEN_LIFETIME', 604800), // 7 days
    
    // Other settings...
];
```

Add to your `.env`:

```env
JWT_SECRET=your-super-secret-jwt-key-minimum-32-characters-long
JWT_ACCESS_TOKEN_LIFETIME=900
JWT_REFRESH_TOKEN_LIFETIME=604800
```

## Understanding the Built-in Security

### Rate Limiting

All endpoints have built-in rate limiting:
- **Auth endpoints**: 5 login attempts per minute
- **CRUD reads**: 100-200 requests per minute
- **CRUD writes**: 20-50 requests per minute
- **Bulk operations**: 5-10 requests per minute

### Token Security

- **JWT tokens** with secure algorithms (HS256)
- **Session tracking** in auth_sessions table
- **Automatic expiration** and refresh
- **Device fingerprinting** and IP tracking
- **Token invalidation** on logout

### Database Security

- **UUID-based identification** (not sequential IDs)
- **Secure password hashing** (PHP's password_hash)
- **Foreign key constraints** for data integrity
- **Audit logging** for all operations
- **Soft deletes** where appropriate

## Example: Adding Custom Business Logic

If you need custom logic, extend the existing controllers:

```php
<?php

namespace App\Controllers;

use Glueful\Controllers\ResourceController;

class ProductController extends ResourceController
{
    protected bool $enableOwnershipValidation = true;
    
    public function post(array $params, array $data): Response
    {
        // Custom validation
        if ($data['price'] < 0) {
            return Response::error('Price must be positive', 400);
        }
        
        // Add creator info
        $data['created_by'] = auth()->user()->uuid;
        
        // Call parent method
        return parent::post($params, $data);
    }
}
```

Then register custom routes in `routes/api.php`:

```php
<?php

use App\Controllers\ProductController;
use Glueful\Routing\Router;

// Custom product routes (override default resource routes)
$router->post('/products', [ProductController::class, 'post'])->middleware(['auth']);
```
