# CRUD with Validation + Repository in 15 Minutes

This tutorial demonstrates how to build a complete CRUD application using Glueful's built-in repository pattern and validation system. You'll learn to leverage the framework's BaseRepository, Validator, and dual ID system for professional data management.

## What You'll Build

A `Product` management system with:
- ✅ Full CRUD operations with repository pattern
- ✅ Input validation with custom rules  
- ✅ Dual ID system (auto-increment + UUID)
- ✅ Professional error handling
- ✅ Database transactions
- ✅ Automatic audit logging

## Prerequisites

- Fresh Glueful project
- Understanding of [JSON API tutorial](./1.json-api-15min.md)
- Database connection configured

## Step 1: Create the Products Table

Create a migration using Glueful's dual ID pattern:

```bash
php glueful migrate:create CreateProductsTable
```

Edit the migration file in `database/migrations/`:

```php
<?php

namespace Glueful\Database\Migrations;

use Glueful\Database\Migrations\MigrationInterface;
use Glueful\Database\Schema\Interfaces\SchemaBuilderInterface;

/**
 * Create Products Table Migration
 * 
 * Creates the products table following framework patterns:
 * - Both id (auto-increment primary) and uuid (external API) fields
 * - Proper validation and indexing
 * - Timestamp tracking
 */
class CreateProductsTable implements MigrationInterface
{
    public function up(SchemaBuilderInterface $schema): void
    {
        $schema->createTable('products', function ($table) {
            // Dual ID system - framework standard
            $table->bigInteger('id')->primary()->autoIncrement();
            $table->string('uuid', 12);
            
            // Product fields
            $table->string('name', 255);
            $table->text('description')->nullable();
            $table->decimal('price', 10, 2);
            $table->integer('stock_quantity')->default(0);
            $table->string('category', 100)->nullable();
            $table->string('status', 20)->default('active');
            $table->timestamp('created_at')->default('CURRENT_TIMESTAMP');
            $table->timestamp('updated_at')->nullable();
            $table->timestamp('deleted_at')->nullable();
            
            // Add indexes
            $table->unique('uuid');
            $table->index('status');
            $table->index('category');
            $table->index('created_at');
        });
    }

    public function down(SchemaBuilderInterface $schema): void
    {
        $schema->dropTable('products');
    }
}
```

Run the migration:

```bash
php glueful migrate:run
```

**That's it!** Your products table now has a complete REST API automatically:

- `GET /products` - List all products (with pagination, filtering)
- `GET /products/{uuid}` - Get single product by UUID  
- `POST /products` - Create new product
- `PUT /products/{uuid}` - Update product by UUID
- `DELETE /products/{uuid}` - Delete product by UUID

## Step 3: Add Custom Validation and Business Logic

The built-in CRUD API works great, but let's add custom validation and business logic by extending `ResourceController`:

Create `app/Controllers/ProductController.php`:

```php
<?php

declare(strict_types=1);

namespace App\Controllers;

use Glueful\Controllers\ResourceController;
use Glueful\Http\Response;
use Glueful\Auth\UserIdentity;
use Glueful\Helpers\Utils;
use Glueful\Validation\Validator;
use Glueful\Validation\Rules\{Required, Type, Length, Range};

class ProductController extends ResourceController
{
    private Validator $validator;
    
    public function __construct()
    {
        $this->setupValidator();
    }
    
    /**
     * Override post method to add validation and business logic
     */
    public function post(array $params, array $data): Response
    {
        // Validate input data
        $errors = $this->validator->validate($data);
        if (!empty($errors)) {
            return Response::error('Validation failed', 422, ['errors' => $errors]);
        }
        
        // Use filtered/sanitized data
        $cleanData = $this->validator->filtered();
        
        // Add UUID if not provided
        if (!isset($cleanData['uuid'])) {
            $cleanData['uuid'] = Utils::generateUuid();
        }
        
        // Add automatic fields
        $cleanData['status'] = $cleanData['status'] ?? 'active';
        
        // Custom business logic - check for duplicate names
        if ($this->isDuplicateName($cleanData['name'])) {
            return Response::error('Product name already exists', 422, [
                'errors' => ['name' => ['Product name must be unique']]
            ]);
        }
        
        // Call parent method with enhanced data
        return parent::post($params, $cleanData);
    }
    
    /**
     * Override put method for update validation
     */
    public function put(array $params, array $data): Response
    {
        // Create update validator (without required rules)
        $updateRules = [
            'name' => [new Type('string'), new Length(1, 255)],
            'description' => [new Type('string'), new Length(0, 1000)],
            'price' => [new Type('numeric'), new Range(0.01, 999999.99)],
            'stock_quantity' => [new Type('integer'), new Range(0, 999999)],
            'category' => [new Type('string'), new Length(1, 100)],
            'status' => [new Type('string')]
        ];
        
        // Only validate provided fields
        $filteredRules = [];
        foreach ($data as $field => $value) {
            if (isset($updateRules[$field])) {
                $filteredRules[$field] = $updateRules[$field];
            }
        }
        
        $updateValidator = new Validator($filteredRules);
        $errors = $updateValidator->validate($data);
        
        if (!empty($errors)) {
            return Response::error('Validation failed', 422, ['errors' => $errors]);
        }
        
        $cleanData = $updateValidator->filtered();
        
        // Check for duplicate name on update (exclude current product)
        if (isset($cleanData['name']) && $this->isDuplicateName($cleanData['name'], $params['uuid'])) {
            return Response::error('Product name already exists', 422, [
                'errors' => ['name' => ['Product name must be unique']]
            ]);
        }
        
        return parent::put($params, $cleanData);
    }
    
    /**
     * Add custom endpoint for low stock products
     */
    public function getLowStock(array $params, array $queryParams): Response
    {
        $threshold = (int) ($queryParams['threshold'] ?? 5);
        
        // Add low stock filter
        $queryParams['stock_quantity__lt'] = $threshold;
        $queryParams['status'] = 'active';
        
        return parent::get($params, $queryParams);
    }
    
    /**
     * Add custom endpoint for product statistics
     */
    public function getStats(): Response
    {
        // Use the repository to get statistics
        $repository = $this->getRepository();
        
        $totalProducts = $repository->count(['status' => 'active']);
        $lowStockProducts = $repository->count([
            'status' => 'active',
            'stock_quantity__lt' => 5
        ]);
        $categories = $repository->distinct('category', ['status' => 'active']);
        
        return Response::success([
            'total_products' => $totalProducts,
            'low_stock_products' => $lowStockProducts,
            'total_categories' => count($categories),
            'categories' => $categories
        ]);
    }
    
    /**
     * Check if product name already exists
     */
    private function isDuplicateName(string $name, ?string $excludeUuid = null): bool
    {
        $repository = $this->getRepository();
        
        $filters = [
            'name' => $name,
            'status' => 'active'
        ];
        
        if ($excludeUuid) {
            $filters['uuid__ne'] = $excludeUuid;
        }
        
        return $repository->count($filters) > 0;
    }
    
    /**
     * Setup validation rules for products
     */
    private function setupValidator(): void
    {
        $rules = [
            'name' => [
                new Required(),
                new Type('string'),
                new Length(1, 255)
            ],
            'description' => [
                new Type('string'),
                new Length(0, 1000)
            ],
            'price' => [
                new Required(),
                new Type('numeric'),
                new Range(0.01, 999999.99)
            ],
            'stock_quantity' => [
                new Type('integer'),
                new Range(0, 999999)
            ],
            'category' => [
                new Type('string'),
                new Length(1, 100)
            ],
            'status' => [
                new Type('string')
            ]
        ];
        
        $this->validator = new Validator($rules);
    }
}
```

## Step 4: Register Custom Routes

Add custom routes to override the default resource routes in `routes/api.php`:

```php
<?php

use App\Controllers\ProductController;
use Glueful\Routing\Router;

/** @var Router $router */

// Custom product routes (override default resource routes)
$router->group(['prefix' => '/products', 'middleware' => ['auth']], function(Router $router) {
    // Standard CRUD routes with custom validation
    $router->get('/', [ProductController::class, 'get']);
    $router->post('/', [ProductController::class, 'post']);
    $router->get('/{uuid}', [ProductController::class, 'getSingle']);
    $router->put('/{uuid}', [ProductController::class, 'put']);
    $router->delete('/{uuid}', [ProductController::class, 'delete']);
    
    // Custom endpoints
    $router->get('/low-stock', [ProductController::class, 'getLowStock']);
    $router->get('/stats', [ProductController::class, 'getStats']);
});
```

## Key Framework Features Used

### 1. Built-in CRUD System
- **Zero Setup**: Migration creates instant REST API
- **ResourceController**: Extend for custom validation and business logic
- **Dual ID System**: Auto-increment for performance, UUID for external APIs
- **Automatic Responses**: Consistent JSON response format with `success`, `message`, `data`

### 2. Validation System
- **Rule-Based**: Composable validation rules (Required, Type, Length, Range)
- **Mutating Rules**: Can transform data during validation
- **Filtered Results**: Get sanitized data after validation
- **Custom Validation**: Easy to add business logic validation

### 3. Repository Pattern (Under the Hood)
- **Automatic Repository**: ResourceController uses BaseRepository internally
- **Transaction Support**: Built-in transaction handling
- **Connection Management**: Handles database connections efficiently
- **Query Builder**: Advanced filtering and pagination

### 4. Framework Architecture Benefits
- **Batteries Included**: Full CRUD without boilerplate code
- **Extensible**: Override only what you need to customize
- **Consistent**: All resources follow the same patterns
- **Production Ready**: Built-in security, rate limiting, audit logging

## Pro Tips

1. **Start with built-in CRUD** - Only customize when you need specific business logic
2. **Use UUIDs in APIs** - Keep internal IDs private for security
3. **Extend ResourceController** - Don't build controllers from scratch
4. **Leverage validation rules** - Compose rules for complex validation scenarios
5. **Use framework response patterns** - Maintain consistency with `success`, `message`, `data` format
6. **Test validation thoroughly** - Ensure your custom rules work as expected

### Framework Philosophy
- **Start Simple**: Migration → Instant API
