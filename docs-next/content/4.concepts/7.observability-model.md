# Observability Model

Observability in Glueful is a layered contract: every request produces correlatable logs; optionally emits metrics and (roadmap) traces; and supplies structured hooks for permission, rate limit, and caching decisions. The design favors low overhead, graceful degradation, and upgrade paths toward OpenTelemetry without coupling the core to a single vendor.

## Pillars & Principles

| Pillar | Current State | Design Principles |
|--------|---------------|-------------------|
| Metrics | In-process collection via `MetricsMiddleware` → `ApiMetricsService` (async batching) | Non-blocking, batched flush, minimal cardinality dimensions |
| Logging | Structured (JSON recommended) through framework logger config (see `logging.php`) | Correlate with `request_id`, avoid log spam, semantic levels |
| Tracing | Lightweight span wrapper (`TracingMiddleware`) behind `TracerInterface` | No-op by default, pluggable adapter for OTLP/OpenTelemetry |
| Events (future) | Planned domain/event bus instrumentation | Standard naming, optional sampling |
| Profiling (future) | CPU/heap snapshots triggerable in debug | Off by default, controlled via env flag |

Guiding principles: (1) Never fail a user request due to telemetry, (2) Keep correlation primitives consistent, (3) Provide extension surfaces for deeper instrumentation.

## Request Correlation Model

| Correlation Element | Source | Propagation |
|---------------------|--------|-------------|
| request_id | Generated early (helper `request_id()`) | Added to metrics payload, tracing span attribute, log MDC |
| user_uuid | Populated post-auth if available (session / token) | Span attribute `enduser.id`, log context, metrics aggregation (future) |
| route | Router match or raw path | Metrics `endpoint`, span `http.route`, log field |
| trace/span id (future) | Tracer adapter | Injected into response headers (roadmap) |

If a third-party proxy provides `X-Request-ID`, you can adopt it as the seed value for continuity across upstream layers.

## Metrics Architecture

`MetricsMiddleware` wraps each request:
1. Capture start time (microseconds).
2. Execute downstream stack.
3. Measure latency (ms) + status code + method + endpoint.
4. Enqueue metric via `ApiMetricsService::recordMetricAsync()`.

`ApiMetricsService` characteristics:
- Caches pending metrics (default threshold: 50) in `CacheStore` before batch insert.
- Stores raw rows + daily aggregates (aggregate tables maintain rolling counts & latency sums).
- Performs silent failure handling—exceptions logged but never bubble into request path.
- Periodically purges stale metrics (30‑day raw window / 1‑year aggregates).

### Collected Fields (Raw Metric)
| Field | Type | Purpose |
|-------|------|---------|
| endpoint | string | Stable identifier (path) for aggregation |
| method | string | HTTP method segmentation |
| response_time | int (ms) | Latency measurement |
| status_code | int | Error rate & SLO separation |
| is_error | bool | Quick filter for 5xx / app exceptions |
| timestamp | datetime | Time series bucket alignment |
| ip | string | Rate / abuse diagnostics (anonymize in strict privacy contexts) |
| request_id | string? | Log/trace correlation (in memory stage) |

### Metrics Use Cases
| Goal | Query Pattern (Aggregates) |
|------|---------------------------|
| P95 latency per endpoint | (total_response_time / calls distribution + percentiles offline) |
| Error budget tracking | error_count / calls by day |
| Capacity planning | calls trend slope over recent weeks |

## Structured Logging Model

Logging config (see `logging.php`) should emit JSON lines containing at least:
`timestamp`, `level`, `message`, `request_id`, `endpoint`, `user_uuid?`, `trace_id?`.

### Recommended Log Categories
| Category | Intent |
|----------|--------|
| access | High-level request summary (start/end or just end) |
| app | Business events (state transitions, domain success) |
| security | Auth failures, permission denials, rate limiting triggers |
| audit | Critical state changes (role assignment, data export) |
| perf | Slow query warnings, cache miss clusters |

### Log Volume Controls
- Use sampling (e.g., only log full payload for 1% of successful high-throughput endpoints).
- Collapse repetitive warnings into aggregated counters (future metrics integration).
- Avoid logging whole request bodies containing PII—mask systematically.

## Tracing (Current & Roadmap)

`TracingMiddleware` uses `TracerInterface` to start a parent span `http.request` with attributes (`http.method`, `http.route`, `user_agent`, `net.peer.ip`, optional `glueful.request_id`).

Current baseline:
- Span closed after response.
- Attaches `http.status_code` + `enduser.id` when available.
- Default tracer is a no-op or simple in-memory stub (implementation dependent) so adding middleware does not degrade latency.

Roadmap enhancements:
| Feature | Description |
|---------|-------------|
| Child spans | Automatic instrumentation around DB queries / cache misses |
| Exporters | OTLP / Zipkin / Jaeger adapters via service provider |
| Baggage propagation | Inject/extract W3C trace headers for distributed tracing |
| Span events | Permission decision events appended as span events |
| Span links | Tie async queue job spans back to originating request |

## Permission & Security Instrumentation

Integrate with the Gate pipeline (see [Permission Model](./5.permission-model.md)) by:
- Emitting debug logs (conditional) for DENY decisions with reason code (future structured enumeration).
- Recording aggregate permission decision latency metrics (planned: histogram) at PermissionManager boundary.
- Adding span events `permission.check` with attributes: `permission`, `decision`, `strategy`, `voters_consulted` when tracing is active.

Rate limiting & abuse detection may increment counters keyed by `ip`+`endpoint` (currently internal to metrics service). Future: promote to explicit metric families (e.g., `rate_limit_block_total`).

## Performance & Sampling Strategy

| Layer | Default Overhead Target | Approach |
|-------|-------------------------|----------|
| Metrics | < 1% request time | In-memory timing only; async batch write |
| Logging | Configurable | Avoid per-line heavy JSON encoding for high-volume routes (sample) |
| Tracing | Near 0% when disabled | No-op tracer, conditional code paths |
| Future Events | Bounded | Batched dispatch / ring buffer |

Sampling recommendations:
| Signal | Approach |
|--------|----------|
| Traces | Head-based 1-5% in production; tail-based for error cases (roadmap) |
| Access logs | 100% but optionally degrade verbose fields under surge |
| Permission checks | Summaries + aggregated counts; verbose denied detail behind debug flag |
| Slow queries | Threshold logging (e.g., >300ms) with once-per-key cooldown |

## Extension Points

| Extension | Mechanism | Example |
|-----------|-----------|---------|
| Custom tracer | Bind `TracerInterface` to implementation | OpenTelemetry tracer provider |
| Metrics sink | Decorate `ApiMetricsService` or add queue consumer | Export to Prometheus via sidecar |
| Log enricher | Middleware adding MDC fields | A/B test bucket, tenant id |
| Span decorators | Event listeners (future) | Add DB row counts to spans |
| Error reporter | Error handling pipeline hook | Send 5xx to Sentry/Rollbar |

Keep extension logic fail-safe; wrap remote calls with timeouts.

## Anti-Patterns

| Anti-Pattern | Problem | Safer Alternative |
|--------------|---------|------------------|
| Blocking DB writes inside request metrics path | Latency amplification | Async cache queue + batch flush |
| Logging full PII payloads | Compliance & security risk | Redact or hash sensitive fields |
| High-cardinality labels (e.g., user UUID as metric label) | Metric store explosion | Use user category or sample subset |
| Emitting traces w/out sampling in high RPS service | Cost & noise | Apply head sampling & dynamic rate control |
| Swallowing all errors silently | Lost diagnostics | Log at least aggregated error counters |

## Roadmap

| Area | Planned Enhancement |
|------|---------------------|
| Metrics | Prometheus exporter / pull endpoint, percentile pre-computation |
| Tracing | OTLP exporter, DB & cache automatic instrumentation |
| Logging | Structured request lifecycle summary line (single-line JSON) |
| Permissions | Decision histogram + reason code enumeration |
| Rate Limiting | Metrics surface for adaptive score + block durations |
| Error Handling | Unified error event emission for correlation across layers |
| SLA/SLO | Burn rate calculators for latency & error budgets |

## Practical Examples

### Minimal Correlated Log (JSON example)
```json
{"level":"info","message":"request.complete","request_id":"abc123","endpoint":"/api/posts","status":200,"duration_ms":43}
```

### Tracing Middleware Span (conceptual)
```
Span http.request
	attributes: http.method=GET http.route=/api/posts http.status_code=200 glueful.request_id=abc123 enduser.id=uuid-7
```

### Recording Custom Metric (Extension)
```php
$metrics = app(ApiMetricsService::class);
$metrics->recordMetricAsync([
	'endpoint' => '/jobs/queue-size',
	'method' => 'SYSTEM',
	'response_time' => 0,
	'status_code' => 200,
	'timestamp' => time(),
	'ip' => '127.0.0.1',
	'is_error' => false,
]);
```
